# 固定資産台帳 PDF の取込（AI への手順）

固定資産台帳（減価償却資産の明細）の PDF を読んで、減価償却資産評価アプリ（asset-valuation）の
**案件JSON** を作るための手順。読むのは AI（Claude）、確かめるのは人。サーバも DB も使わない。

```
台帳 PDF ──(AI が読む)──▶ 案件JSON の下書き ──▶ normalize_asset_case（MCP・検査と正規化。書き込みはしない）
         ──▶ AI が PDF の隣へ保存（R0xMMDD_{案件名}_減価償却資産評価.json）
         ──▶ 人がアプリの Step 1「JSONファイルから復元」で読み、Step 3 の「取込の確認」で見終える
```

- 正規化の知識（区分の別名・償却方法・和暦・金額の読み方）はアプリの `src/domain/` にあり、
  MCP の `normalize_asset_case` はそれをそのまま使う。**ここに書いてある以上の変換を AI 側でしなくてよい**
  （和暦・カンマ付きの金額・「15年」は台帳の書き方のまま渡してよい）
- おかしな値でも行は落とさない。ツールが注意を付けて返すので、それを人に報告する
- 架空のサンプル: `test-data/固定資産台帳_ダミー.md` → `test-data/asset-valuation-intake-sample.json`

## 1. 先に人から聞くこと

| 項目 | 例 | 無いとき |
|------|------|------|
| 案件名 | `ダミー商事株式会社 様` | 台帳の会社名＋「 様」で作り、報告で確かめる |
| 課税時期 | `令和8年3月31日`（相続開始日） | **聞く**（推測しない。どの期末を使うかが決まらない） |

## 2. 読むもの・読まないもの

**読む**: 台帳の本体の行（1資産1行）、一括償却資産の明細、繰延資産の明細。

**読まない**:

- ページ小計・頁計・科目計・合計の行（金額の突き合わせにだけ使う → 5.）
- **除却・売却・滅失した資産**（「除却」「売却」「廃棄」の記載、期末簿価の欄が「—」や空欄で除却日があるもの）。
  課税時期より後の除却なら課税時期には持っていたので**読む**（迷ったら読んで `uncertain` と `note` に書く）
- 土地・借地権・電話加入権・建設仮勘定（減価償却資産ではない。アプリの区分にも無い）
- リース資産の明細（所有していない。会社の資産として計上されていれば読み、`note` に「リース資産」と書く）

**期末簿価は課税時期の直前の期末**のものを使う。台帳に「前期末」「当期末」の2列があれば、
課税時期以前で一番新しい期末の列。課税時期が期の途中なら、その期首（＝前期末）の簿価。
どの列か分からない台帳は `uncertain: true` にして報告で聞く。

## 3. 1行の書き方

```json
{
  "no": "001",
  "name": "本社事務所",
  "category": "建物",
  "method": "定額法",
  "acquisitionDate": "H22.4.1",
  "usefulLife": "50年",
  "acquisitionCost": "48,000,000",
  "bookValue": "30,624,000",
  "source": { "file": "固定資産台帳.pdf", "page": 1, "note": "1頁 1行目" }
}
```

| 項目 | 書き方 |
|------|------|
| `no` | 台帳の資産番号を**文字列のまま**（`"001"`・`"230-1"`。先頭ゼロ・枝番を消さない）。番号が無ければ `""` |
| `name` | 台帳の名称のまま。空欄なら `""`（ツールが注意を付ける。推測で埋めない） |
| `category` | 台帳の科目のまま（`建物付属設備`・`器具備品`・`ソフトウエア`・`車両` など。別名はツールが解決する） |
| `method` | 償却方法の欄のまま（`定額法`・`定率法`・`旧定率法`・`250%定率法`）。欄が無い・空なら書かない（区分の既定を当てて注意が付く。評価額には影響しない） |
| `acquisitionDate` | 台帳の書き方のまま（`H22.4.1`・`令和5年8月1日`・`2023/8/1`）。日が読めなければ**年月だけ**書く（`R5.8`。1日として注意が付く） |
| `usefulLife` | 耐用年数（`15`・`"15年"`）。一括償却資産は `3`。繰延資産・簿価評価の区分は無くてよい |
| `acquisitionCost` | 取得価額（繰延資産は支出額）。`"1,234,567"`・`"△1,000"` のままでよい |
| `bookValue` | 2. で決めた期末の帳簿価額 |
| `hasFixedAssetTaxRecord` / `isRental` | **書かない**（台帳からは分からない。人が Step 3 で決める） |
| `source.file` | PDF のファイル名（必須） |
| `source.page` | PDF のページ（1始まり） |
| `source.note` | 何行目か、読み取りの補足（「手書きの訂正あり」「日がかすれて読めない」） |
| `source.uncertain` | 読み取りに自信が無いとき `true`（かすれ・見切れ・桁が怪しい・どの列か迷った） |

### 和暦の読み方

- `M`=明治・`T`=大正・`S`=昭和・`H`=平成・`R`=令和。`H27.4.1`・`H27/4/1`・`平成27年4月1日`・`令和元年5月1日` はどれも読める
- 元号の境目（平成31年4月30日 → 令和元年5月1日）は台帳のまま書く。期間外の日付（`平成31年5月1日`）はツールが読んだうえで注意を付ける
- `R5.8.□` のように日が読めないときは `R5.8` と書き、`note` に理由を書く

### 耐用年数の読み方

- 台帳の「耐用年数」欄の年数。`15年`・`15` どちらでもよい
- 「償却率 0.133」のように**率しか無い台帳**は年数へ直さず `uncertain: true` にして `note` に率を書く（人が年数を入れる）
- 中古資産の見積耐用年数は台帳の年数のまま

## 4. 区分ごとの扱い（SPEC 2.3.4）

| 台帳 | `category` | 備考 |
|------|------|------|
| 建物・建物付属設備・構築物・機械装置・車両運搬具・器具備品・生物・ソフトウエア | 台帳の科目のまま | 評価は定率法残価率など（アプリが計算する） |
| 特許権・商標権・意匠権・実用新案権・のれん（営業権） | 台帳の科目のまま | 簿価で評価 |
| **一括償却資産**（20万円未満・3年均等） | `一括償却資産` | 明細が年度ごとの1行なら年度ごとに1行（名称に年度を入れる。例: `パソコン一式（R6年度分）`）。耐用年数 3 |
| **少額減価償却資産**（30万円未満の即時償却） | `少額減価償却資産` | 台帳に載っていれば読む（簿価0でも行は作る。帳簿と突き合わせるため） |
| **繰延資産**（創立費・開業費・開発費・株式交付費・社債発行費） | 台帳の名称（`創立費` など）か `繰延資産` | 財産性なし（評価額0）。取得価額は支出額、簿価は期末残高 |

区分が台帳から決められないとき（科目欄が無い・独自の科目名）は、台帳の文字をそのまま `category` に入れる。
ツールが工具器具備品にして候補つきの注意を付けるので、報告で挙げる。

## 5. 組み立てと検査

案件の形:

```json
{
  "version": "1.1",
  "caseName": "ダミー商事株式会社 様",
  "taxDate": "令和8年3月31日",
  "assets": [ … 3. の行 … ]
}
```

1. 全行を `assets` に入れて MCP の **`normalize_asset_case`** に `case` として渡す（ファイルは書かない・何度呼んでもよい）
2. 返ってくるもの: 正規化した `caseJson`、行ごとの `warnings`、`totals`（件数・取得価額・期末簿価の合計と区分別）、保存名 `fileName`
3. **`totals` を台帳の頁計・合計と突き合わせる**。合わなければ読み落とし・二重読み・小計行の混入を探して直し、もう一度呼ぶ
4. 合ったら `caseJson` を **PDF と同じフォルダ**に `fileName`（`R0xMMDD_{案件名}_減価償却資産評価.json`）で保存する。
   同名のファイルがあれば上書きせず人に聞く

`case` の形が成り立たない（案件名・課税時期・`assets` が無い）ときだけツールはエラーを返す。

## 6. 最後の報告（人へ）

次の順に短く書く。

1. 保存したファイルのパス
2. 件数（読んだ行・読み飛ばした行とその理由: 小計 n 行・除却 n 件 など）
3. 合計の突き合わせ: 取得価額・期末簿価の合計を台帳の合計と並べる（区分別に台帳の科目計があればそれも）。一致／不一致
4. 確かめてほしい行: `uncertain` にした行と、ツールが注意を返した行（NO・名称・理由）
5. 人が決めること: 建物・建物附属設備の**賃貸の有無と固定資産税の評価明細の有無**（台帳からは分からない）

アプリで読み込むと、4. と 5. の行は Step 3 の「取込の確認」に同じ分け方で並ぶ。
