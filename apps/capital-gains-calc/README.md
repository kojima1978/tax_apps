# 譲渡所得税 計算ツール

不動産（土地・建物）および株式等の譲渡にかかる所得税・復興特別所得税・住民税を試算するツールです。
いずれも分離課税なので、他の所得とは切り離して計算します。

## 機能

- **タブ切替**: 「不動産」と「株式等」で計算体系が異なるため、入力欄・結果表示ごと分離
- **2列レイアウト（PC）**: 画面幅1024px以上では左に入力、右に計算結果とミニマムタックスを並べる（入力しながら結果を見られる）。狭い画面では1列に戻る
- **算式に沿った入力**: 不動産タブの入力欄は「売却の情報 → 取得費 → 譲渡費用 → 特例の適用」の順。譲渡所得の算式（譲渡価額 − 取得費 − 譲渡費用）の3項がそのままセクションになっている
- **譲渡費用の内訳入力**: 仲介手数料・印紙税・測量費・建物取壊費用・その他の5項目に分けて入力し、合計を自動計算。内訳は結果表と印刷物にも残る
- **仲介手数料の自動計算**: 「譲渡価額から計算」ボタンで宅建業法の報酬上限（速算式・消費税込み）を入力欄へ流し込む。入るのは**上限額**なので、押した後に実額へ書き換えられる（譲渡価額を変えても追従しない）
- **印紙税の自動計算**: 同じく「譲渡価額から計算」ボタン。売買代金の区分に応じた**契約書1通分**の額（軽減措置適用後）が入る
- **長期／短期判定**: 譲渡した年の**1月1日時点**の所有期間で自動判定（譲渡日基準ではない）
- **減価償却の自動計算**: 非事業用建物は構造を選ぶだけで償却費相当額を算出（旧定額法・取得価額の95%が上限）。事業用は償却費累計額を手入力
- **建物の取得価額の算出**: 土地建物を一括で購入していて建物の価額が分からない場合に、合計額を土地と建物へ分ける。「直接入力 / 消費税から逆算 / 固定資産税評価額で按分 / 建築価額表から算出」の4方式で、算出過程を①②③…の行で表示。算出根拠は結果の注記に載るので印刷物にも残る
- **概算取得費**: 取得費が不明な場合の5%概算。実額より概算が有利なとき（実額 < 譲渡価額の5%）は差額を添えて結果画面で指摘（不動産・株式等の両タブ）
- **主要な特例**: 居住用財産の3,000万円特別控除 / 所有期間10年超の軽減税率（6,000万円以下14.21%）/ 相続財産を譲渡した場合の取得費加算
- **手取り概算**: 譲渡価額 − 譲渡費用 − 税額合計。**内訳3行を再掲**してから手取りで締める（画面・印刷とも）。3つの数字はいずれも上の表に出ているが離れた位置に散るので、手取りの行だけを見て検算できるようにしている
- **納付タイミングで区切った税額表**: 「所得税 → 復興特別所得税 → **小計** → 住民税 → 税額合計」の順。申告書の並びではなく、いつ納めるかで切っている（小計まで＝確定申告で納付、住民税＝翌年度に別途）。税率区分が1つのときは合計行を立てない（明細と同じ数字の繰り返しになるため）
- **納付時期の案内**: 所得税・復興特別所得税は翌年3月15日までの確定申告、住民税は翌年6月以降に別途——を注記に出す。住民税は納付が半年ずれるうえ普通徴収なら年4回に分かれ、資金繰りの想定が狂いやすい
- **前提が確定していないことの明示**: 取得日・譲渡日が未入力だと短期税率になるため、注記だけでなく結果表の区分名にも「日付未入力」と添える（「短期譲渡所得（日付未入力・税率 39.63%）」）
- **ミニマムタックス判定**: 基準所得金額が3億3,000万円を超える場合の追加課税（措法41条の19・令和7年分以後）。該当者は稀なのでチェックボックスで開く方式
- **参考資料**: 税率一覧・**居住用財産の特例の主な要件**・非事業用建物の償却率表・ミニマムタックスの概要（既定では印刷対象外。印刷メニューで2枚目として追加できる）
- **印刷対応**: **A4横1枚**に収まる2段組レイアウト（計算結果 → ミニマムタックスの順に段へ流し込む。**入力欄は印刷しない**＝内容が結果表に再掲されるため。事務所名・担当者・作成日はタイトルと同じ行のヘッダー帯）。縦の間隔は既定でゆとりを持たせ、行数が倍近くなるミニマムタックス印刷時だけ詰める
- **印刷内容の選択**: 印刷ボタンのポップオーバーで、参考資料を含めるかを選ぶ（含めた場合も**参考資料だけで1枚**に収まる。計 2枚）
- **備考欄**: 画面のテキストエリアに書いた内容がそのまま印刷物に載る。用紙の余った高さを全部取るので、入力量にかかわらず下端に空白が残らない（参考資料の2枚目は手書き用の空枠）。**未入力なら枠ごと印刷せず**、空きが足りていれば代わりに税率一覧を空きの中央へ刷り込む
- **担当者名**: 画面上部のヘッダーで入力すると印刷物のヘッダー帯に載る。未入力なら手書き用の下線だけが印刷される

## 税額計算ロジック

| 項目 | 計算方法 |
|:-----|:---------|
| 譲渡所得金額 | 譲渡価額 − （取得費 + 取得費加算額） − 譲渡費用 |
| 取得費（実額） | 土地の取得価額 + 建物の取得価額 − 償却費相当額（建物の取得価額は直接入力のほか、後述の3方式で算出できる） |
| 取得費（概算） | 譲渡価額 × 5% |
| 償却費相当額（非事業用） | 建物の取得価額 × 0.9 × 旧定額法の償却率 × 経過年数（取得価額の95%が上限） |
| 経過年数 | 取得日〜譲渡日。6ヶ月以上の端数は1年に切上げ |
| 課税譲渡所得金額 | 譲渡所得金額 − 特別控除（居住用財産 最大3,000万円） |
| 長期譲渡（所有期間5年超） | 所得税15% + 復興0.315% + 住民税5% = 20.315% |
| 短期譲渡（所有期間5年以下） | 所得税30% + 復興0.63% + 住民税9% = 39.63% |
| 軽減税率（居住用・10年超） | 6,000万円以下の部分: 所得税10% + 復興0.21% + 住民税4% = 14.21%<br>6,000万円超の部分: 長期譲渡の税率 |
| 株式等 | 所得税15% + 復興0.315% + 住民税5% = 20.315%（上場・一般とも同率） |
| 復興特別所得税 | **所得税額 × 2.1%**（譲渡所得に直接掛けない） |

税率は結果表の各行に括弧書きで併記する（「所得税（15%）」「住民税（5%）」）。参考資料は既定で
印刷対象外なので、本紙だけを見ても適用税率が分かるようにしている。区分名に付く税率も
「短期譲渡所得（税率 39.63%）」のように**同じ括弧書きで1行に収める**。

**結果表の行は補足を持たない**（`ResultRow` に注記用のフィールドを置かない）。ラベルの下に
小さい文字で1行足すと、その行だけ高さが変わって表が揃わなくなる。補足したいことは括弧書きで
ラベルに入れるか、注記リスト（`NoteList`）へ回す。

税目の内訳（`taxTotalRows`）は**納付タイミングで区切る**。申告書の並び（所得税・復興・住民税）ではなく、
確定申告で一緒に納める所得税＋復興特別所得税で**小計**を挟んでから、翌年度に別途納付する住民税を出す。
明細行はインデントし、小計と税額合計だけを行頭に揃えて「明細 → 結果」で読めるようにしている
（納付時期そのものは上記のとおり行には書かない）。

```
短期譲渡所得（税率 39.63%）            55,000,000円
  所得税（30%）                       16,500,000円
  復興特別所得税（所得税額の2.1%）        346,500円
小計                                 16,846,500円
  住民税（9%）                        4,950,000円
税額合計                              21,796,500円
```

**税率区分が1つならこれが唯一の明細**で、税目ごとの合計行は立てない（同じ数字の繰り返しにしかならない）。
軽減税率で区分が2つに割れるときだけ、区分ごとの明細に続けて同じ形の合計（`total` 付き）を出す。
合計行に税率を併記しないのは、区分ごとに違って1つに定まらないため。

手取り概算も同じ並びで、譲渡価額・譲渡費用・税額合計の3行を先に置いて手取りで締める。

### 建物の取得価額の算出（土地建物を一括で取得した場合）

中古住宅を土地建物まとめて購入していると、契約書に建物の価額が書かれていないことがある。
それでも譲渡所得の計算では建物だけを減価償却するので、合計額を土地と建物に分ける必要がある。
実額取得費のときだけ出る「建物の取得価額の求め方」で4方式から選ぶ（既定は直接入力）。

| 方式 | 計算方法 |
|:-----|:---------|
| ① 直接入力 | 契約書等で区分されている金額をそのまま入力（既定） |
| ② 消費税から逆算 | 建物（税抜）＝ 建物の消費税額 ÷ 税率<br>建物の取得価額 ＝ 建物（税抜）＋ 消費税額<br>土地 ＝ 合計取得価額 − 建物の取得価額 |
| ③ 固定資産税評価額で按分 | 建物（税抜）＝ 合計取得価額 ÷（土地評価額÷建物評価額 ＋ 1 ＋ 税率）<br>建物の取得価額 ＝ 建物（税抜）×（1＋税率）<br>土地 ＝ 合計取得価額 − 建物の取得価額 |
| ④ 建築価額表から算出 | 新築時の価額 ＝ 建築価額表の単価（円/㎡）× 延べ床面積<br>建物の取得価額 ＝ 新築時の価額 − 新築から購入までの償却費相当額<br>土地 ＝ 合計取得価額 − 建物の取得価額 |

**選択肢の並びがそのまま優先順位**（国税庁）。①契約書で区分されていればそれを使い、
②建物の消費税額が分かれば割り戻し、③どちらも不明なら建築価額表による、という順になる。
固定資産税評価額による按分は法令上の定めがある方法ではないが、実務で広く使われるので
選択肢に入れている（トグルでは②のすぐ後ろ）。

③は**合計取得価額に建物の消費税が含まれている**前提。土地は非課税なので按分比をそのまま
掛けると建物の消費税分だけ過大になる。合計 ＝ 土地 ＋ 建物税抜 ＋ 建物税抜×税率 を建物税抜について
解いてから消費税を足し戻す（円単位。売主が個人で消費税がかからない場合は税率に「消費税なし」を選ぶ）。

④の償却費相当額は**新築から購入までの分**で、購入日以後の償却は通常どおり取得費の計算側で行う
（同じ `calcNonBusinessDepreciation` を使うので95%上限もそのまま効く）。取得日が未入力なら
控除しない＝新築で取得した場合の計算になる。

②③の消費税率は「取得日から」ボタンで取得日時点の税率を入れられる。**引上げ時の経過措置**
（指定日までの契約は旧税率）は判定できないので、あくまで既定値として入るだけ。

#### 建物の標準的な建築価額表

出典は国税庁「譲渡所得の申告のしかた」付表。国土交通省「建築着工統計」の工事費予定額÷床面積から
求めた1㎡当たりの単価（千円/㎡）で、**昭和34年（1959年）〜令和5年（2023年）**の建築分を収録している。

構造区分は**木造・木骨モルタル造／鉄骨鉄筋コンクリート造／鉄筋コンクリート造／鉄骨造の4区分**しかなく、
減価償却の構造区分（`BUILDING_STRUCTURES` の7区分）とは粒度が違う。そのため価額表の列は
パネル側の専用セレクトで選び、償却率は従来どおり「建物の構造」から引く。**この方式を選んだ間は
事業用でも「建物の構造」を表示する**（新築から購入までの償却に償却率が要るため）。

新築年は登記事項証明書の表題部（新築年月日）で確認する。マンションは専有部分の床面積で差し支えない。

#### 算出根拠を印刷物に残す

算出過程は入力パネル内に①②③…の行で表示するが、**入力欄は印刷しない**ので用紙には出ない。
代わりに1行のサマリ（`BuildingPriceResult.basis`）を `RealEstateInput.buildingCostBasis` 経由で
計算上の補足へ回し、結果表の注記として印刷する。建物価額の求め方は申告時に必ず問われるところなので、
出力した紙だけで根拠が分かるようにしている。

### 仲介手数料の上限額（宅地建物取引業法の報酬額）

| 売買代金 | 上限額（税抜） |
|:---------|:---------------|
| 400万円超 | 売買代金 × 3% + 6万円 |
| 200万円超 400万円以下 | 売買代金 × 4% + 2万円 |
| 200万円以下 | 売買代金 × 5% |

自動計算ボタンが入れるのは上記に**消費税10%を加えた額**（円未満切捨て）。譲渡費用として計上するのは
実際に支払った額なので、上限額と異なる場合は手で書き換える。低廉な空家等の特例（800万円以下・33万円）は
「空家等」の判定を伴うため自動計算には含めていない。

### 印紙税（印紙税法 第1号文書）

売買契約書に記載された金額で決まる階段方式。仲介手数料と同じく譲渡価額から自動入力できる。

| 記載金額 | 軽減後 | 本則 |
|:---------|-------:|-----:|
| 1万円未満 | 非課税 | 非課税 |
| 〜10万円 | 200円 | 200円 |
| 〜50万円 | 200円 | 400円 |
| 〜100万円 | 500円 | 1,000円 |
| 〜500万円 | 1,000円 | 2,000円 |
| 〜1,000万円 | 5,000円 | 10,000円 |
| 〜5,000万円 | 10,000円 | 20,000円 |
| 〜1億円 | 30,000円 | 60,000円 |
| 〜5億円 | 60,000円 | 100,000円 |
| 〜10億円 | 160,000円 | 200,000円 |
| 〜50億円 | 320,000円 | 400,000円 |
| 50億円超 | 480,000円 | 600,000円 |

軽減措置（措法91）は**令和9年3月31日まで**に作成された契約書に適用。判定は本来「契約書の作成日」だが、
このツールは契約日を持たないので**譲渡日で代用**している（契約は期限内・引渡しは期限後、という
組合せは拾えない）。入るのは**契約書1通分**なので、売主が2通分を負担した場合などは書き換える。

### ミニマムタックス（極めて高い水準の所得に対する課税・措法41条の19）

令和7年分以後の所得税に適用。分離課税の譲渡所得は税率が低いため、所得が大きいほど負担率が下がる
（いわゆる「1億円の壁」）ことへの是正措置。

| 項目 | 計算方法 |
|:-----|:---------|
| 基準所得金額 | 課税譲渡所得金額（特別控除**後**）+ その他の合計所得金額 |
| 基準所得税額 | 譲渡所得に対する所得税額 + その他の所得に対する所得税額（いずれも**復興特別所得税を含まない**／外国税額控除の適用前） |
| 追加納付額 | （基準所得金額 − 3億3,000万円）× 22.5% − 基準所得税額（プラスの場合のみ） |
| 復興特別所得税 | 追加納付する所得税額 × 2.1% |
| 住民税 | 影響しない（追加課税は所得税のみ） |

判定は不動産タブ・株式等タブの結果を**合算**して行う（基準所得金額はその年の全所得の合算のため）。
適用年分の判定には不動産タブの譲渡日を使い、未入力の場合は本年とする。

### 特例の要件（参考資料の2枚目）

3,000万円の特別控除（措法35条）と軽減税率の特例（措法31条の3）は、チェックボックスを入れれば
計算には反映されるが、**適用できるかどうかの判定はしていない**。要件はチェックボックスの
1行ヒントに収まらないので、`ReferenceTables` の「居住用財産の特例の主な要件」に箇条書きで置いた
（出典: 国税庁タックスアンサー
[No.3302](https://www.nta.go.jp/taxes/shiraberu/taxanswer/joto/3302.htm) /
[No.3305](https://www.nta.go.jp/taxes/shiraberu/taxanswer/joto/3305.htm)）。

前年・前々年の特例適用歴、買換え特例との関係、親族間譲渡の除外など、**入力値からは判定できない
要件**が多いのがこの2つの特例の特徴で、ツール側で自動判定するより一覧を渡すほうが実務に合う。

### 対象外（本ツールでは扱わない）

譲渡損失の損益通算・繰越控除、買換え特例、空き家の3,000万円特別控除、収用等の特別控除、
総合課税となる資産（ゴルフ会員権・書画骨とう等）の譲渡。

## 画面レイアウト（PCの2列）

画面幅1024px以上では `.screen-split` を2列グリッドにして、左に入力フォーム、
右に計算結果とミニマムタックスを置く。右列は `.screen-split-side` でひとまとめにしてある
（結果とミニマムタックスを別々のグリッド項目にすると、行の高さが左の入力欄に引っ張られて
間が大きく空くため）。

このメディアクエリは **`screen and` を必ず付ける**。A4横の印刷幅は約1070pxあり、
`min-width: 1024px` だけだと印刷時にも当たって段組（`.print-columns`）を壊す。

## 印刷レイアウト

A4横1枚。用紙面積はA4縦と同じなので、横向きにしただけでは1枚にならない。
内容量そのものを次の3点で削っている（`globals.css` の `@media print`）。

- **参考資料を印刷しない**: 税率一覧・償却率表・ミニマムタックス概要は既定では `display: none`
- **入力欄を印刷しない**: `.form-section { display: none }`。譲渡価額・取得費の内訳・譲渡費用の内訳は
  すべて結果表に再掲されるので、印刷すると同じ数字が2度出るうえ用紙に収まらない
- **2段組**: `.print-columns`（計算結果＋ミニマムタックス）に `column-count: 2`

入力欄を出さないと、結果表に載らない前提条件（譲渡日・取得日・所有期間・建物の用途と構造・
適用した特例）だけが失われる。これは `RealEstateResult` の `conditions` が1行にまとめ、
見出し直下に `.print-conditions` として印刷する（画面では出さない）。株式等タブは
区分（上場／一般）が見出しに、取得費の実額・概算の別が結果表の行ラベルに出ているので補足は不要。

段の切れ目で表が割れないよう `.result-block` に `break-inside: avoid`、見出しに
`break-after: avoid` を置いている。`.result-grid` は grid のままだと段をまたげないため、
印刷時だけ `display: block` に戻す（計算結果側だけは後述の帯に組み替えるので例外）。
ミニマムタックスの入力欄は `.form-section` の外にあるので、
`.input-item` などの印刷用ルールはそのまま残してある。

ミニマムタックスは判定を有効にしたときだけ印刷される（無効時は `no-print`）。
有効・無効いずれの場合も、特例をすべて適用した最大構成で1枚に収まることを確認済み。

### 計算結果は3つの帯（`column-span: all`）

`.result-section` の中身をそのまま段に流すと、見出しと `.print-conditions` が**左段の頭だけ**を
消費するため、「譲渡所得の計算」が「税額の計算」より下から始まる（実測 y=128 と y=82）。
段組は新聞流しなので、左段に何を置いても右段の開始位置は動かない。

そこで `.result-section` の直下4要素（`h2` / `.print-conditions` / `.result-grid` / `.note-list`）に
`column-span: all` を付け、**〈見出し＋前提条件〉〈2つの表〉〈計算上の補足〉**の3つの帯として
紙幅いっぱいに置く。2つの表は段組ではなく専用の2列グリッド
（`grid-template-columns: 1fr 1fr` / `gap: 0 6mm`）で横に並べる。

2表の上端は `align-items: stretch` でそろう。**表そのものは伸ばさない**（`table` に
`height: 100%` を足すと下端もぴたりと合う代わりに、行数の少ない表の行が伸びる。
3,000万円控除で税額が0になる構成が最大で 17px → 41px と2.4倍になり、値が
間延びして見える）。行数の差は下端の空きとして残し、`.result-grid` の
`border-bottom` で枠として閉じてそろえる。

**行の高さは全構成・両表で同じ**（ゆとり17px・詰め14px）。行を増減しても
この値は動かない。

ミニマムタックスは帯にしない。あちらを `column-span: all` にすると段の高さが62px増えるうえ、
見出しと注記が左に残るため中の2表は結局そろわない（実測）。

### 縦の間隔（`--pr-*` トークン）

行間・ブロック間を詰め切ると、内容の少ない構成では紙の上半分に全部積み上がって見える。
一方でミニマムタックスまで刷る構成は表が40行を超えており、**1行あたり 0.5px 広げるだけで
20px 以上**効くため、ゆとりを入れると備考を書いたときに2枚目へ溢れる（実測 778px > 740.8px）。

そこで縦の間隔は `@media print` 内の `body` にトークンとして持たせ、**ミニマムタックスを
印刷する構成のときだけ**詰めた値へ落とす。切り替えは `body:has(.minimum-tax-section:not(.no-print))`
で、React 側にフラグを増やさずに済ませている。

| トークン | ゆとり | 詰め | 用途 |
| --- | --- | --- | --- |
| `--pr-gap` | 9px | 4px | 表・ブロック間、免責・備考・ヘッダー帯の下 |
| `--pr-gap-sm` | 5px | 3px | 見出し（h2）の下、副題、ヘッダー帯の罫線まで |
| `--pr-gap-xs` | 3px | 2px | 小見出し（h3）の下、注記の内側 |
| `--pr-rule-gap` / `--pr-rule-pad` | 11px / 7px | 6px / 4px | 罫線区切りの上下 |
| `--pr-cell-y` / `--pr-cell-lh` | 1.5px / 1.3 | 0.8px / 1.22 | 表のセル上下と行間 |

実測（A4横 = 740.8px、`.print-sheet` の高さ）。`.print-remarks` は `flex: 1` で残りを全部取るので、
**余裕は備考欄のテキストエリアの高さに出る**（1行あたり約14px）:

| 構成 | 表の行数（譲渡／税額） | 行の高さ | 段組の高さ | 用紙の高さ | 備考欄の記入域 |
| --- | --- | --- | --- | --- | --- |
| 不動産・全特例・ミニマムタックス（詰め） | 15 / 6 | 14px | 476px | 741px | 146px |
| 不動産・全特例（ゆとり） | 15 / 6 | 17px | 371px | 741px | 232px |
| 不動産・実額・特例なし（ゆとり） | 14 / 10 | 17px | 354px | 741px | 249px |
| 不動産・概算・特例なし（ゆとり） | 11 / 10 | 17px | 316px | 741px | 287px |
| 株式等（ゆとり） | 5 / 9 | 17px | 259px | 741px | 344px |

いずれも譲渡費用4項目と取得費加算額を埋めた状態での実測。段組の高さを決めるのは
**行数の多い側の表**なので、**そちらに1行足すと詰め構成で約14px**、備考欄がその分狭くなる
（行数の少ない側に足しても、空きが埋まるだけで用紙の高さは変わらない）。
行を増やすときはここを実測し直すこと。

`:has()` が効かないブラウザでは全構成がゆとり側になり、ミニマムタックスを含む最大構成
だけが2枚に割れる（Chrome 105+ / Edge / Safari 15.4+ / Firefox 121+ は対象外）。

### 用紙1枚の組み方（`.print-sheet`）

1枚分の内容は `.print-sheet` でくくり、印刷時は `display: flex` / `flex-direction: column` /
`min-height: 196mm`（A4横 210mm − 上下マージン 7mm×2）にする。**段組はこの中の
`.print-columns` だけ**にかけるので、タイトル・事務所情報・免責・備考欄は段組の外にあり、
`column-span: all` を使わなくてよい（使うのは段の中の `.result-section` だけ）。

末尾の `.print-remarks`（備考欄）が `flex: 1` で残りの高さを全部取る。内容量は入力次第で
大きく変わる（特例オフ・ミニマムタックスオフだと半分近く空く）ので、余った分を「余白」ではなく
「記入欄」として見せるための枠。`min-height` にしてあるのは、内容が 196mm を超えたときに
切り捨てず溢れさせるため。

`RemarksBox` は `onChange` の有無で2つの姿を持つ。渡せば画面のテキストエリア（`App.tsx` の
`remarks` を編集し、そのまま印刷される。枠線は `.print-remarks` 側が持つので印刷時の
`textarea` は罫線なしで枠内を埋める）、省略すれば手書き用の空枠になる。2枚目の参考資料側は
後者を使う。

### 備考が未入力のとき

枠もラベルも印刷しない。`textarea` のプレースホルダ（「印刷物に反映されます」）は
印刷にも出てしまうため、`.print-remarks-empty` で丸ごと消している。

空いた高さには**税率一覧を刷り込む**（`.print-fill`）。入るかどうかは残り高さ次第なので、
判定は**コンテナクエリ**に任せる。空きが 155px 未満なら何も印刷しない（見出し＋表の実測は
144px）。JS で測らないのは、画面の高さと印刷レイアウトの高さが一致しないため
（測るには印刷CSSの再現が要る）。

刷り込む位置は**空きの中央**（`.print-fill-slot` を `justify-content: center`）。
本文の直後に続けると空きが下にまとめて残って「上に積んだだけ」に見え、逆に下端へ寄せると
紙の縁に貼り付いて見える。上下に同じだけ空きを残すのが収まりが良い。

判定用の `.print-fill-slot` を `position: absolute; inset: 0` で挟んでいるのは、
**flex-grow で決まる高さを Chrome が「不定」と扱い、`@container (min-height:)` が一切
当たらない**ため。`inset: 0` なら高さが親から確定するので判定できる（`min-width` は
flex-grow でも当たるので、高さ側だけの制約）。

参考資料を2枚目に付けるときは同じ表が2度出るので、`.print-with-reference .print-fill` で
刷り込みを止める。税率一覧は `RateTable` に切り出して参考資料と共用している。

事務所名・担当者・作成日（`PrintMeta`）はタイトルと同じ帯（`.print-header-band`）に入れ、
**左にタイトル・右に事務所情報**の1行に組む（gift-tax-simulator の印刷ヘッダーと同じ形）。
右側は `<address>` の3行（事務所名／住所＋TEL／担当＋作成日）で、電話番号と作成日を
それぞれ前の項目と同じ行に置いて行数を減らしてある。2行に分けるとその分だけ本文が減るので、
罫線もこの帯が持って1行にまとめている。
以前は用紙の最下部にフッターとして置いていたが、下端は備考欄が埋めるので上へ移した。**画面上では出さず**
（`.print-meta { display: none }`）、事務所名と担当者入力は上部の固定ヘッダーに統合してある。
担当者名は `App.tsx` が持ち、ヘッダーの入力欄と `PrintMeta` の両方へ配る。

### 印刷内容の選択（参考資料の2枚目）

印刷ボタンはポップオーバーを開き、含める内容を選ばせる。本紙（入力・計算結果）は常に印刷するので
選択肢に出さず、任意なのは参考資料だけ。選択肢は `lib/print-options.ts` の `PRINT_OPTIONS` に定義し、
状態は `App.tsx` が持って `<main>` に `print-with-reference` クラスを付ける。印刷スタイル側はこの
クラスの有無だけを見る。

参考資料を含めた場合も**A4横1枚を超えない**。`.reference-sheet` が `.print-sheet` と同じ
「196mm ＋ 末尾に備考欄」の組み方を共有し、`break-before: page` で2枚目に送る。本紙の2段組
（段幅 約520px）の中に混ぜると本紙が溢れるため、参考資料は段組の外に出したうえで
`.ref-tables` の中だけを2段組に組み直している。改ページで免責などが一緒に2枚目へ送られないよう、
`.reference-sheet` は `App.tsx` で**DOM上いちばん後ろ**に置いてある。

参考資料は4ブロック（税率一覧 144px / 特例の要件 249px / 償却率表 168px / ミニマムタックス 187px）で、
2段に分かれて 741px に収まっている（実測）。ブロックを足すときは合計ではなく**2段に割った後の高さ**を
見ること。`.ref-block` は `break-inside: avoid` なので、収まらないブロックは丸ごと3枚目へ送られる。
