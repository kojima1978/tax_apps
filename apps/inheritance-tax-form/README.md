# Inheritance Tax Form（相続税の申告書）

相続税の申告書の各様式を画面上で作成・印刷するWebアプリケーション。
国税庁様式の罫線をそのまま再現し、様式1つ＝A4縦1枚に収まる形で印刷できる。

第11の2表 / 第11・11の2表の付表1 / 同（続）/ 同（別表1）/ 第13表 / 第14表 / 第15表 / 第15表（続）

**実装済み（24・全て）**: 第1表・第1表（続）・第2表・第4表・第4表の2・第5表・第6表・第7表・第8の8表・第9表・第10表・第11表・
第11表の付表1〜4・第11の2表・第11・11の2表の付表1・同（続）・同（別表1）・第13表・第14表・第15表・第15表（続）

> 「第11表の付表1〜4」（財産の明細書）と「第11・11の2表の付表1」（小規模宅地等の特例）は
> 名前が似ているだけの別の様式。


現在はフロントエンドのみ（バックエンド・DBなし）。入力内容はブラウザの localStorage に保存する。

- サイドバーの様式名をクリックすると本文がその様式に切り替わる
- 見出し「様式を選択」の右の矢印ボタンでサイドバーを開閉できる（閉じると幅48pxの帯になり、用紙の表示幅が広がる）。
  開閉状態は `inheritance-tax-form:sidebar` に保存する。**申告内容（`inheritance-tax-form:v1`）とは別キー**にして、
  JSON保存/読込・クリアの対象から外している
- 初回表示はPCでは開き、800px以下の画面では閉じる。モバイルで開いた一覧は高さを制限し、一覧内をスクロールする
- チェックした様式が提出（印刷）対象。**印刷はチェックした様式だけを登録簿の順に連続出力する**
- 第1表は必須、第1表（続）は財産を取得した人が2人以上のときに自動で付くのでチェックを操作できない
- 付表は「人」ではなく「財産」の一覧なので枚数を人数から決められない。用紙の下の `−／＋` で増減する
- 第11の2表は**贈与を受けた人1人につき1枚**を自動で用意する。1枚に年分6行しか無いので、
  精算課税の贈与が7年分以上ある人は用紙の下の `−／＋` で同じ人の枚数を増やせる。
  **記入が1つも無い人の分は印刷しない**（画面には出す）
- 第4表は**1枚に加算の対象となる人4人分**。誰が2割加算の対象かは続柄コードだけでは決められない
  （代襲相続人・養子・遺贈を受けた第三者などが混ざる）ので、**人数から枚数を自動で決めず**、
  用紙の下の `−／＋` で増減する（既定1枚）。氏名は項番→氏名の選択式
- 第4表の2も**1枚に控除を受ける人3人分**。贈与税を課税されていたかどうかは相続の情報から
  決められないので、第4表と同じく**人数から枚数を自動で決めず**、用紙の下の `−／＋` で増減する
- 第7表も**常に1枚**（1の各段5人・2の(1)(2)とも5人）。用紙に繰越欄が無く枚数を増やせない
- 第5表は配偶者1人分の様式なので**常に1枚**。続柄コードが「01 配偶者」の人を配偶者として扱い、
  その人がいないときは何も計算しない（枚数の増減も無い）
- 第8の8表は1つの用紙に2つの節（1 税額控除額・2 納税猶予税額）が載り、**どちらも2人分／枚**。
  控除・猶予の対象になるかは相続人の一覧からは決められないので、**人数から枚数を自動で決めず**、
  用紙の下の `−／＋` で増減する（既定1枚）。氏名は項番→氏名の選択式
- 第9表は1の保険金の明細5件・2の相続人5人で1枚。どちらが足りなくても用紙の下の `−／＋` で増やす
- 第10表も同じく1の明細5件・2の相続人5人で1枚。用紙の下の `−／＋` で増やす
  （2の相続人は自動では増えない — 保険金を受け取った相続人だけを書く欄なので人数と一致しない）
- 第13表は債務4件・葬式費用5件で1枚。件数が多いときは用紙の下の `−／＋` で増やす。
  3の「債務などを承継した人」が1枚に4人分しか入らないので、**財産を取得した人が5人以上いると
  枚数は自動で増える**（`−` はその下限までしか減らせない）
- 第14表は1つの用紙に3つの節（1 暦年課税分の贈与財産・2 出資持分の定めのない法人などへの遺贈・
  3 特定の公益法人などへの寄附）が載る。節ごとに件数が違い、どれが足りなくても用紙を増やすので、
  **枚数は表全体で1つ**（用紙の下の `−／＋`・既定1枚）。合計欄は最終ページにだけ出す
- 第15表は罫線も欄も（続）と完全に同じで、違うのは左列の見出しだけ（第15表は「各人の合計」、
  （続）は財産を取得した人の氏名）。そのため定義は `table15.ts` 1本で、列の指定だけを差し替える。
  **（続）は第15表にチェックが付いていて、かつ人数が2人以上のときだけ自動で付く**
- 第11・11の2表の付表1は**小規模宅地等の明細3件で1枚**。4件目からは（続）（5件／枚）へ続き、
  **（続）は件数から自動で枚数が決まる**（チェックは操作できない）
- 別表1は「一の宅地等」ごとに1枚。用紙の下の `−／＋` で増やす。
  **どの明細がどの別表1の何行目かは、付表1の下にある画面だけの `<select>` で対応づける**
  （様式には印刷しない。対応づけると付表1の③④が読み取り専用の転記欄になる）
- 様式の登録簿は `App.tsx` の `FORMS` 配列。様式を足すときはここに1行追加する。
  人数から枚数が決まる様式（`auto`）は `autoPages` にも1行足す
- 付表4種は作りが同じなので、画面も `App.tsx` の `DETAIL_SPECS` から組み立てている
  （付表を足すときは `FORMS` と `DETAIL_SPECS` に1行ずつ）

## 様式の再現方式（GridForm）

背景画像を敷かず、**罫線そのものを CSS グリッドで引く**。stock-valuation-form と同じ方式。

- セルは `{ top, left, width, height }` を**パーセント**で宣言する（`src/forms/*.ts`）
- `snapLines()` が誤差 0.3% 以内の罫線をまとめ、`grid-template-columns/rows` を `fr` で生成する
- 文字サイズは `fitFontSize()` が枠の実寸から算出して自動で縮める。
  様式は同じ幅の枠に文字数の違うラベルを詰め込むため、文字数だけで決めると
  「算出税額（第３表⑬）」のような長いラベルが枠からはみ出す
- 縦書きの帯（「この申告書が修正申告書である場合」等）は `writing-mode` で表現する

セルの生成は `src/forms/geometry.ts` にまとめてある。人ごとの列（`personColumn`）、
被相続人の列（`decedentColumn`）、①〜㉗の行（`calcRows`）はすべてここのファクトリが返すので、
第1表と第1表（続）で同じ定義を共有できる。

付表1〜4は「8明細×3行＋項番＋分割が確定した財産」という同じ骨格を持つので、
組み立ては `detail.ts` に1本化してある。ただし**罫線の実測pxは様式ごとに違う**
（4様式は別々に版が起こされていて、表の幅は付表1が 1037px・付表2が 1105px…と一致しない）。
そのため座標は共有せず、様式ごとの `DetailFrame` として `table11f?.ts` が持つ。
付表3・付表4は組の中の横罫線が3行のグリッドと揃わないため、`rowLines` と `bands` で
「どの罫線からどの罫線まで」を明示する。

第11・11の2表の付表1と（続）は逆に**縦罫が一律 35px ずれているだけ**で列構成が同じなので、
`col()` を1本だけ持ち、上下端と行の位置を `F1Sheet` として差し替えている
（（続）は「この表は…」の前書きと限度面積の判定欄が無く、明細が3件でなく5件）。

## フィールド名の規約

`GridForm` は `g(field)` / `u(field, value)` の2関数だけで値をやり取りする。
保存先は接頭辞で振り分ける（`useFormData` の `splitField`）。

| 接頭辞 | 保存先 |
|--------|--------|
| `c.` | 共通欄（被相続人・提出先・第2表㋭） |
| `t.` | 自動計算欄（「各人の合計」列と様式間の転記欄・書き込み不可） |
| `h0.` `h1.` … | 財産を取得した人 N番目 |
| `l0.` `l1.` … | 第2表の法定相続人 N番目 |
| `table11f1#0.` `table11f2#0.` … | 付表（財産の明細書）の様式ID＋明細の通し番号 |
| `table1112f1#0.` | 小規模宅地等の明細（本表3件＋（続）5件／枚を通した通し番号） |
| `table1112f1b#0.` | 別表1の「一の宅地等」の通し番号 |

## 自動計算

自動計算は `src/lib/calc.ts` に閉じている。

### 第1表・第1表（続）

| 欄 | 算式 |
|----|------|
| ④ 純資産価額 | ①＋②−③（赤字は0） |
| ⑥ 課税価格 | ④＋⑤（1,000円未満切捨て） |
| ⑧ あん分割合 | 各人の⑥ ÷ Ⓐ（小数2位）。相続税法基本通達17－1に従って合計を1.00に調整し、⑲の合計税負担が最小となる人へ0.01の端数を自動配分 |
| ⑨ 算出税額 | ⑦ × ⑧（円未満切捨て） |
| ⑮ 計 | ⑫＋⑬＋⑭ |
| ⑯ 差引税額 | ⑨＋⑪−⑮（⑩が記入されていれば⑩＋⑪−⑮。赤字は0） |
| ⑲ 小計 | ⑯−⑰−⑱（黒字は100円未満切捨て） |
| ㉑ / ㉒ | ⑲−⑳ が黒字なら㉑、赤字なら㉒（還付） |
| ㉖ 小計の増加額 | ⑲−㉓ |
| ㉗ 納付／還付 | （㉑又は㉒）−㉕（還付は△。黒字は100円未満切捨て） |
| 「各人の合計」列 | 各行の横計。Ⓐは⑥の合計、⑧の合計欄は様式どおり `1.00` 固定 |

### 第2表（相続税の総額の計算書）

| 欄 | 算式 |
|----|------|
| ㋑ 課税価格の合計額 | 第1表Ⓐ（＝⑥の合計）を自動転記 |
| ㋺ 法定相続人の数 | ④欄に氏名を書いた人数 |
| ㋩ 遺産に係る基礎控除額 | 3,000万円＋600万円×㋺（万円単位） |
| ㋥ / ㋬ 課税遺産総額 | ㋑−㋩ ／ ㋭−㋩（基礎控除以下なら0） |
| ⑥ / ⑨ 法定相続分に応ずる取得金額 | ㋥×⑤ ／ ㋬×⑤（1,000円未満切捨て） |
| ⑦ / ⑩ 税額 | 速算表（`RATE_BRACKETS`）で ⑥（⑨）×税率−控除額 |

第3表は未対応のため、第2表㋭および第3表側の⑨〜⑪は読み取り専用・計算対象外とする。
| ⑧ / ⑪ 相続税の総額 | ⑦（⑩）の合計（100円未満切捨て） |

④法定相続人は第1表の「財産を取得した人」から選択し、氏名・続柄を自動連動する。
第1表側の氏名・続柄を変更した場合も第2表へ反映される。㋭「第3表⑥Ⓐ」だけが手入力
（第3表は未対応）。⑤法定相続分は分子・分母を入力する。

### 第4表（相続税額の加算金額の計算書）

一親等の血族（代襲相続人を含む）及び配偶者**以外**の人は相続税額が2割加算される。

| 欄 | 算式 |
|----|------|
| ① 税額控除前の相続税額 | その人の第1表⑨（⑩に記入があれば⑩） |
| ② 一親等の血族であった期間内の精算課税財産の価額 | 手入力 |
| ③ 課税価格に算入された財産の価額 | その人の第1表①＋②＋⑤ |
| ④ 加算の対象とならない相続税額 | ⌊①×②÷③⌋（②が空のときは計算しない） |
| ⑤ 管理残額がある場合の加算の対象とならない相続税額 | 手入力（第4表の付表Ⓐ。付表は24帳票の対象外） |
| ⑥ 相続税額の加算金額 | ⌊①×0.2⌋。**④又は⑤があるときは ⌊（①−④−⑤）×0.2⌋** |

- 手入力は②⑤と氏名（項番→氏名の選択式）だけ。①③④⑥は自動
- ⑥は第1表のその人の⑪になるので、`computeAll()` は**第5表の配偶者の⑬と同じ3周目**で
  ⑪を上書きして⑯以降を計算し直す。⑨は⑪に依存しないので循環しない
- 枠内の（注）2にある大かっこの図は罫線表に置けないため `〔…〕×〔…〕÷〔…〕` のテキストで表す
- 縦書きの帯（「相続時精算課税に係る贈与を受けている人で、かつ…」）は**列が左から右へ進む**ので、
  `GridCell` の `verticalLr` で `writing-mode: vertical-lr` にしている（他の縦書きは `vertical-rl`）

### 第4表の2（暦年課税分の贈与税額控除額の計算書）

相続開始の年の前年分・前々年分・前々々年分の**3つのブロックが縦に並ぶだけ**で、
どのブロックも「特例贈与財産4行＋一般贈与財産4行」という同じ骨格を持つ。
そのため `table42.ts` は行の y だけを `BLOCK_Y`（ブロック×罫線）に持ち、
ラベルも「前年／前々年／前々々年」を差し込んで組み立てる。

| 欄 | 算式 |
|----|------|
| ④ 控除を受ける贈与税額（特例贈与財産分） | ⌊③×②÷①⌋ |
| ⑧ 同（一般贈与財産分） | ⌊⑦×⑥÷⑤⌋ |
| ⑫ / ⑯ | 前々年分の同じ算式（⌊⑪×⑩÷⑨⌋ / ⌊⑮×⑭÷⑬⌋） |
| ⑳ / ㉔ | 前々々年分の同じ算式（⌊⑲×⑱÷⑰⌋ / ⌊㉓×㉒÷㉑⌋） |
| ㉕ 暦年課税分の贈与税額控除額計 | ④＋⑧＋⑫＋⑯＋⑳＋㉔ |

- 手入力は提出先（署）・年・①②③⑤⑥⑦…（各ブロックの前3行）だけ。**4行目は自動**

上位桁だけを状態に持ち、計算時のみ `SCALE` 倍して円に戻す。表示・保存が様式の記載と一致する。

**空欄の扱い**: 算式に使う欄が1つも埋まっていない行は 0 ではなく空欄のままにする（白紙の様式を0で埋めない）。

## 入力補助

- 生年月日の元号（1:明治〜5:令和）と続柄（01:配偶者、11:長男 …）は記載要領等のコードから選択式（`src/data/codes.ts`）
- 付表1〜4のコード欄（細目コード／口座種別等コード、特例、金融商品取引業者等・金融機関等・支店等コード、国外）も
  記載要領のコード表から選択式（`src/data/detailCodes.ts`）。**細目コードを選ぶと隣の「細目」「口座種別等」に
  名称が自動で入る**が、読み取り専用にはしない（付表3の「99 上記以外」・付表4の「73 その他」は自分で書くため）
- コード欄は**印刷だけ**が「コードの数字だけ」になる（`compactSelectedOption`）。
  **画面は選択後も選択肢の名称ごと出す**（「01 配偶者」）。枠が狭いので長い名称は切れるが、
  何を選んだのかが一目で分かることを優先している（欄をコードだけにすると開き直さないと読めない）
- 「該当する欄に『1』と記入」の欄（取得原因・参考記載・修正申告・税理士法）は取り得る値が
  空欄と「1」しかないので**空欄／1 の選択式**（`geometry.ts` の `flag()`）
- 記載要領由来で間違えやすい点を2つコード表側に閉じ込めてある。
  **金融機関のコードは付表2と付表3で違う**（付表2は 6:証券・7:上記以外、付表3は 5:漁協・6:上記以外）。
  **特例の番号も様式ごとに使える範囲が違う**（付表1は1〜6、付表2は3・6〜8、付表4は2・4・6、付表3に欄は無い）
- 細目コードには第15表の転記先（`table15`）も持たせてある。
  細目ごとの合計をどの欄へ持っていくかは記載要領で決まっているのでコード表を唯一の定義元にする。
  **利用区分によっては転記先が1欄増える**（付表1の記載要領 注1・注2）ので、その例外も
  `table15Extra` としてコード表に持たせた。宅地の「配偶者居住権に基づく敷地利用権」は③に加えて⑦へ、
  家屋等の「配偶者居住権」は⑩に加えて⑪へ。判定は**完全一致**で行うこと —
  「配偶者居住権の目的となっている建物」は文字列としては「配偶者居住権」を含むが⑪の対象ではない
- 様式にも記載要領にも書かれておらず**記載例にしか出てこない記入条件**は、入力欄のツールチップ
  （`GridCell` の `hint`）として添える。下の「記載例から取り込んだ記入ルール」を参照
- 「※」の付いた欄（※通信日付印の年月日・※確認・※申告期限延長日）は記入不要のため入力欄を置いていない
- **提出先税務署は選択式**（全国524署・`src/data/taxOffices.ts`）。候補は**被相続人の郵便番号の
  都道府県**で絞る（`src/hooks/useZipPrefecture.ts`。郵便番号が未入力・該当なしなら全国524署）。
  同梱しているのは郵便番号→住所だけで**郵便番号→管轄税務署の対応表は持っていない**ので、
  絞れるのは県まで。住所は必ず都道府県名で始まるため先頭一致で判定できる。
  自由入力で保存された古い値は候補の先頭に残して消さない
- **被相続人の郵便番号欄は様式では「記入不要」の斜線**だが、住所の補助と上の絞り込みに要るので
  **画面だけ入力欄**にしてある（`GridCell` の `printDiagonal`）。印刷では中身を隠して斜線に戻す
  （画面用の中身を `no-print`、斜線を `print-only` で出し分ける）
- **郵便番号を7桁入れると住所の上段が自動で入る**（`src/lib/zipAddress.ts`）。
  データは日本郵便の全国一括データ（`utf_ken_all`）を圧縮して同梱したもの（`src/data/zipAddresses.json`・
  12万件・約2.9MB／gzip 約0.9MB）。**7桁そろって初めて動的 import する**ので初期表示には効かない。
  **住所欄が空のときだけ**入れる（打ち替えても手で直した住所は上書きしない）
- **住所欄は枠の高さを変えずに中を上下2段**にしてある（`GridCell` の `twoLine`）。
  上段＝郵便番号から入る「都道府県・市区町村・町域」、下段（`…address2`）＝丁目・番地・建物名。
  様式に中の横罫線は無いので、枠は1つのまま入力欄だけを積んでいる。
  適用は `geometry.ts` の共通部品経由で**第1表の被相続人・財産を取得した人と第1表（続）の全員**
- 郵便番号・電話番号は**先頭の0を落とさない**（`SubInput` の `keepZeros`）。金額欄と違い番号なので、
  「064-0941」「03-…」がそのまま残る
- 入力は変更のたびに localStorage（`inheritance-tax-form:v1`）へ保存される
- JSON保存／読込でファイルとしても持ち出せる

### 代償財産と負数

代償財産は**支払う人が負数・受け取る人が正数**で「取得財産の価額」欄に書く（62ページ）。
そのため付表の同欄と、その転記先である第11表2①③・第1表①は `signedCommaInteger`（△を許す欄）にしてある。
`calc.ts` の `num()` は `△` を負数として読むので、集計もそのまま通る。

付表4に「75 代償財産・価額0・取得者1に△5,000,000・取得者2に5,000,000」と入れると、
第11表2の1人目①③＝△5,000,000／2人目①③＝5,000,000、第1表①も同じ値になることを確認済み。
