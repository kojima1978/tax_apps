## 2. 概要

### 2.1 目的

顧客単位で個人資産、負債、偶発債務を年度別に管理し、次の業務を支援する。

- 現在の貸借対照表の可視化
- 相続発生時の死亡保険金、税金、承継関連費用を含む予測
- 資産・負債明細の個別入力および表形式での一括編集
- 最大3年度の残高比較
- 相続税シミュレーターとのAPI連携
- 顧客単位または全体のJSONバックアップ
- 顧客説明用レポートの印刷・PDF出力

### 2.2 対象ユーザー

- 税理士法人、金融機関等の担当者
- PCでの登録・編集を主用途とし、タブレットやモバイルでの閲覧にも対応する

## 4. 顧客管理

### 4.1 顧客一覧

- 顧客名、顧客名かな、顧客コード、担当者を対象に検索する。ひらがな・カタカナの違いは吸収し、一致部分を強調表示する。
- 1顧客を1行で表示する（顧客コード、顧客名、かな・担当者、最新年度）。
- 表示件数は25件・50件・100件から選べる（既定25件）。ページ切り替えは一覧の下に置く。
- 全件数を表示し、検索中は「該当件数（全件数中）」を表示する。
- 検索欄から上下矢印キーで行を移動し、Enterでその顧客を開く。Escapeで検索語を消す。

### 4.2 顧客項目

| 項目 | 必須 | 制約・用途 |
|---|---:|---|
| 顧客コード | 必須 | 一意。検索および削除確認に使用 |
| 顧客名 | 必須 | 画面・印刷に表示 |
| 顧客名かな | 任意 | 顧客検索に使用 |
| 担当者 | 任意 | 顧客識別情報 |
| 基準通貨 | 必須 | 3文字。通常はJPY |
| 初期年度 | 新規時必須 | 1900～2200 |

### 4.3 新規作成

- 顧客作成時に、指定年度の現在スナップショットを1件作成する。
- 同一顧客コードは登録できない。

### 4.4 削除

- 顧客コードを確認入力し、一致した場合のみ削除できる。
- 顧客削除により、配下の全年度・全明細を連鎖削除する。
- 削除は取り消せないため、画面上で事前バックアップを案内する。

## 5. 年度管理

### 5.1 基本仕様

- 1顧客・1年度につきスナップショットは1件とする。
- 顧客内で最も新しい年度を「現在年度」とする。
- 基準日の初期値は作成年度の1月1日とし、顧客作成時・年度追加時・年度設定から対象年度内の任意の日付へ変更できる。
- 年度は1900～2200の整数とする。

### 5.2 年度追加

| 作成方法 | 明細 | 相続税・その他税金 |
|---|---|---|
| 前年度からコピー | コピーする | コピーする |
| 空の年度を作成 | 0件 | 0円 |

- 既存年度と重複する場合は作成せず、既存年度の編集へ誘導する。
- 現在より新しい年度を作成した場合、従来の現在年度を過年度へ変更し、新年度を現在年度にする。
- 過去の年度を追加した場合、現在年度は変更しない。

### 5.3 年度削除

- 対象年度を確認入力し、一致した場合のみ削除する。
- 顧客に残る唯一の年度は削除できない。
- 現在年度を削除した場合、残存する最新年度を現在年度へ昇格する。

## 6. 貸借対照表

### 6.1 表示区分

資産側と負債・純資産側を面積比で可視化する。金額と構成比を併記する。

#### 資産

- 金融資産
  - 預金・現金
  - 有価証券
  - 生命保険
  - 退職金
- 不動産
  - 居宅
  - 収益不動産
  - 事業用不動産
  - 遊休不動産
  - その他不動産
- 事業用資産
  - 自社株
  - 事業用資産
  - 貸付金
- その他資産

#### 負債・純資産

- 税金
  - 相続税
  - その他税金
- 借入金
  - 住宅ローン
  - 不動産投資ローン
  - 証券担保ローン
  - 事業用借入
  - その他借入金
- その他負債
  - リース債務
  - 未払金
  - 預り敷金・保証金
- 承継関連費用
- 純資産

個人保証は偶発債務としてB/S外に表示し、純資産計算には含めない。

### 6.2 表示シナリオ

| シナリオ | 生命保険 | 退職金 | 税金 | 承継関連費用 |
|---|---|---|---|---|
| 税金なし | 解約返戻金 | 解約手当金 | 0円 | 0円 |
| 税金あり | 死亡保険金 | 死亡退職金 | 相続税＋その他税金 | 顧客単位の設定額 |

計算式:

```text
現在純資産 = 資産合計 - B/S算入負債

相続時予測資産 =
  現在資産合計
  - 生命保険の解約返戻金合計 + 死亡保険金合計
  - 退職金の解約手当金合計 + 死亡退職金合計

相続時予測純資産 =
  相続時予測資産 - B/S算入負債 - 相続税 - その他税金 - 承継関連費用
```

- 死亡保険金・死亡退職金が未入力の明細は、相続時予測では0円として扱い、注意を表示する。
- 外貨建ての死亡保険金・死亡退職金は、登録された円換算レートを乗じる。

## 7. 資産・負債明細

### 7.1 登録区分

| 区分 | DB上の扱い | 純資産への算入 |
|---|---|---:|
| 資産の部 | `side = ASSET` | 加算 |
| 負債の部 | `side = LIABILITY` | 減算 |
| 偶発債務の部 | `side = LIABILITY`、個人保証 | 算入しない |

### 7.2 科目

#### 資産

`DEPOSIT`、`SECURITIES`、`INSURANCE`、`RETIREMENT_ALLOWANCE`、`HOME_REAL_ESTATE`、`REAL_ESTATE`、`BUSINESS_REAL_ESTATE`、`IDLE_REAL_ESTATE`、`OTHER_REAL_ESTATE`、`PRIVATE_SHARES`、`BUSINESS_ASSETS`、`LOAN_RECEIVABLE`、`COLLECTIBLES`

#### 負債・偶発債務

`LOAN_HOME`、`LOAN_INVESTMENT_PROPERTY`、`LOAN_SECURITIES`、`LOAN_BUSINESS`、`LOAN_OTHER`、`LEASE_OBLIGATION`、`ACCOUNTS_PAYABLE`、`DEPOSITS_RECEIVED`、`GUARANTEE`

### 7.3 中分類

| 中分類 | 対象科目 |
|---|---|
| 金融資産 | 預金・現金、有価証券、生命保険 |
| 不動産 | 居宅、収益不動産、事業用不動産、遊休不動産、その他不動産 |
| 事業用資産 | 自社株、事業用資産、貸付金 |
| その他資産 | その他資産 |
| 借入金 | 各借入金 |
| 個人保証 | 個人保証 |

中分類は文字ラベル、区切り線および最小限の色差で識別する。

### 7.4 共通入力項目

- 登録区分
- 科目
- 名称
- 金融機関・保管先等
- 通貨
- 金額
- 円換算レート
- 評価方法
- 備考

円換算時価は次式で保存する。

```text
円換算時価 = round(算出された通貨建て金額 × 円換算レート)
```

### 7.5 評価算式

| 評価方式 | 算式 | 対象 |
|---|---|---|
| `MANUAL` | 入力金額 | 全般 |
| `STOCK` | 株数・口数 × 単価 × 調整率 | 有価証券、自社株 |
| `UNIT_RATE` | 単価 × 調整率 | その他資産 |
| `LAND_ROADSIDE` | 面積 × 路線価 × 調整率 × 持分 | 土地 |
| `LAND_MULTIPLIER` | 固定資産税評価額 × 倍率 × 調整率 × 持分 | 土地 |
| `BUILDING` | 固定資産税評価額 × 倍率 × 調整率 × 持分 | 建物 |

不動産の固有項目は次のとおり。所在地、土地・建物区分、持分の分子・分母を必須とする。

| 項目 | 対象 | 用途 |
|---|---|---|
| 所在地 | 土地・建物 | 明細一覧・不動産一覧の所在地列 |
| 土地・建物区分 | 土地・建物 | 一覧の区分、並び替えの範囲、絞り込み |
| 地目 | 土地 | 一覧の「地目・用途」列 |
| 面積（㎡） | 土地 | `LAND_ROADSIDE` の評価に使用（路線価方式では必須） |
| 小規模宅地等の特例 | 土地 | 相続税の概算での減額（`11.2`） |
| 建物種類 | 建物 | 一覧の「地目・用途」列 |
| 床面積（㎡） | 建物 | 記録および一覧・CSVの面積列。**評価額の計算には使わない** |
| 持分の分子・分母 | 土地・建物 | 全ての不動産の評価算式に乗じる |

- 土地と建物は別明細で登録する。
- 建物は固定資産税評価額から評価するため、床面積を入力しても評価額は変わらない。
- 貸付金は借主を必須とする。自社株の保有株数は発行済株式総数を超えてはならない。

### 7.6 みなし相続財産（生命保険・退職金）

生命保険と退職金は同じ構造で扱う。B/Sには解約返戻金（退職金は解約手当金）が載り、相続時予測ではそれを給付金へ置き換える。

| 項目 | 生命保険 | 退職金 |
|---|---|---|
| 保管先・支給元 | 保険会社 | 支給元・勤務先 |
| 種類 | 保険種類 | 退職金の種類 |
| 証券番号 | あり | － |
| 被保険者 | あり | － |
| B/S計上額 | 解約返戻金 | 解約手当金 |
| 給付金 | 死亡保険金 | 死亡退職金 |
| 受取人 | あり（複数可） | あり（複数可） |

- 受取人は親族関係に登録した人から選ぶ。複数受取人は分子・分母の分数で取り分を持ち、最大10人まで登録できる。
- 給付金を受取人ごとに割り振るときは、丸めた各人の合計が総額と一致するよう端数を取り分の大きい順に配る。
- **非課税枠の対象かどうかは入力させない。** 受取人が親族関係に登録された法定相続人かどうかで判定する
  （以前は「非課税枠の対象」のチェックで持っていた）。
- 非課税枠（500万円 × 法定相続人数）は生命保険と退職金でそれぞれ別枠とする。
- 受取人が親族関係に登録されていない明細は非課税枠の対象にならないため、その件数を数えて警告に使う。

### 7.7 表で編集・追加

一つの表で登録済み行の編集と新規行の追加を行う。

- 対象: 有価証券、自社株、土地、建物
- 種類ごとに既存明細を読み込み、末尾へ新規行を表示する
- Excel等から複数セルを貼り付け可能
- Enterで次の編集可能セルへ移動
- Shift+Enterで前の編集可能セルへ移動
- 行複製、新規行削除、一括保存に対応
- 登録済み行は表内で更新し、削除は明細一覧の個別削除から行う
- 不動産の表入力金額は千円単位で表示し、保存時に円へ変換する
- 土地は「面積（㎡）」、建物は「床面積（㎡）」を列として持つ。床面積が空欄の行は項目ごと保存しない（0㎡として残さない）

### 7.8 並び替え・絞り込み

#### 並び替え

- ドラッグ＆ドロップ、または並び替えハンドルにフォーカスして上下矢印キーで移動する。
- 入れ替えられるのは**同じ科目どうし**に限る。不動産はさらに**土地・建物が同じもの同士**だけ
  （「居宅・土地」と「居宅・建物」は入れ替えられない）。土地か建物かは保存済みの区分を優先し、
  持っていない古い明細は評価方法が建物・固定資産税評価額方式なら建物、それ以外は土地とみなす。
- 上下矢印キーでの移動は、隣の行が別の範囲なら同じ範囲の行まで読み飛ばす。
- **中分類フィルター・表示順に関わらず並び替えできる。** 上の範囲をまたげないため、
  中分類順で表示していても並びは崩れない。
- 表示中に同じ範囲の明細が他に無い行は、ハンドル自体を無効にする（絞り込みで1件になった場合も含む）。
- 保存に失敗したら並び順を元へ戻す。

#### 表示順・絞り込み

- 表示順は「登録順」「中分類順」「中分類の逆順」から選択できる。既定は中分類順。
  ただし中分類が1種類しかない表は表示順セレクトを出さないため、その場合だけ登録順で開く
  （既定を中分類順にすると手動並び替えへ戻す手段が無くなる）。
- 中分類順の並びは 中分類 → 科目の既定順 → 土地→建物 → 手動の並び の優先順で決める。
  手動の並びが効くのは最下位のみ。
- 中分類フィルターには、不動産に土地・建物の登録があるときだけ中分類の直後に
  「└ 土地」「└ 建物」を字下げして並べる。

### 7.9 明細の削除

- 削除は確認ダイアログを出さず、「元に戻す」を押せる猶予（6秒）を置いてから確定する。
- 猶予中の明細は画面と集計から外す。猶予が過ぎた時点で実際に削除する。
- 猶予中に次の削除を選んだ場合、前の削除はその場で確定する。
- 画面を離れるときは応答を待たずに削除を送信して確定する。
- 削除に失敗した明細は画面へ戻す。

## 8. 不動産一覧

全顧客の不動産を横断して一覧する画面。顧客ごとに明細画面を開き直さずに、登録済みの不動産を見比べるためのもの。
対象は各顧客の**現在年度**のB/Sにある不動産の明細だけとし、過年度は含めない。

### 8.1 表示

| 列 | 内容 |
|---|---|
| 顧客 | 顧客名、顧客コード、年度 |
| 科目・区分 | 科目（居宅・収益不動産等）と土地・建物 |
| 名称・所在地 | 名称と所在地 |
| 地目・用途 | 土地は地目、建物は建物種類 |
| 面積 | 土地は面積、建物は床面積 |
| 持分 | 分子／分母 |
| 固定資産税評価額 | 保持している明細のみ |
| 評価額 | 円換算時価 |

- 未入力の面積・固定資産税評価額は「－」と表示し、0円・0㎡の入力と区別する。
- 並びは 顧客の登録順 → 科目の既定順 → 土地→建物 とする。
- 合計行に、絞り込み後の評価額合計、件数および顧客数を表示する。
- 表示件数は25件・50件・100件から選べる（既定25件）。

### 8.2 検索・絞り込み

- 検索対象は顧客名、顧客名かな、顧客コード、担当者、名称、所在地、地目・用途。ひらがな・カタカナの違いは吸収し、一致部分を強調表示する。
- 科目および土地・建物で絞り込む。検索語と重ねて効く。

### 8.3 明細への移動

- 行のどこを押しても、その明細の資産・負債明細画面（`/customers/{id}/positions?position={明細ID}`）へ移動する。顧客名と名称はリンクとしても辿れる。
- 移動先では対象の行まで画面を送り、短時間だけその行を強調する。**修正モーダルは開かない**（見るつもりの操作で入力欄を開かないため）。
- 強調するかどうかはクエリの有無だけで決め、一定時間後にクエリをURLから外す（再読み込みや「戻る」で再発しない）。

### 8.4 CSV書き出し

- 絞り込み後の全件を書き出す（表示中のページ分だけではない）。
- Excelで開く前提で、BOM付きUTF-8、CRLF改行、全ての値を引用符で囲む。
- 列は 顧客コード、顧客名、顧客名カナ、担当者、年度、B/S基準日、科目、区分、名称、所在地、地目・用途、面積（㎡）、持分、固定資産税評価額（円）、評価額（円）、評価方法、算式、備考。
- ファイル名は `private-banking-properties-YYYYMMDD-HHMM.csv`（JST）。

## 9. 年度比較

- 任意の3年度を選択して比較する。
- 選択年度は自動的に時系列順へ並べる。
- 最新選択年度と直前選択年度の差額を表示する。
- 金融資産、不動産、事業用資産、税金、借入金は小分類を展開できる。
- 年度一覧には基準日、状態、資産合計、負債合計、純資産、個人保証を表示する。

## 10. 親族関係

顧客単位で配偶者・子などの親族を最大20名まで登録する。本人情報は顧客情報画面で管理し、親族関係には含めない。

### 10.0 本人情報

- サイドメニューの「本人情報」専用画面で編集する。
- 氏名、フリガナ、生年月日、顧客コード、担当者を保持する。
- 生年月日は任意とし、B/S基準日時点の年齢を画面上で確認できる。

### 10.1 入力項目

| 項目 | 仕様 |
|---|---|
| 氏名 | 必須、100文字以内 |
| フリガナ | 任意、100文字以内 |
| 続柄 | 配偶者、子、孫、父母、祖父母、兄弟姉妹、甥・姪、その他 |
| 取得原因 | 相続、遺贈、生前贈与、その他 |
| 民法上の法定相続分 | 分子・分母で保持 |
| 税法上の法定相続分 | 分子・分母で保持 |
| 2割加算 | 対象／対象外 |
| 障害者 | 該当なし、一般障害者、特別障害者 |
| 生年月日 | 任意 |

- 行の追加、削除、並び替えを行える。
- 並び替えと削除は、行内のコンパクトなアイコンで操作する。
- PCの入力画面は、全員の項目を見比べながら連続入力できる編集テーブルとする。
- モバイルの入力画面は、同じ項目を行単位のカードへ切り替えて横スクロールを避ける。
- 法定相続分の自動計算を利用できる。計算後は手動で修正できる。
- 自動計算は配偶者と最優先順位の法定相続人から算出し、後順位者は相続分なしとする。

### 10.2 表示

- 登録順に一覧表示する。
- 年齢は表示中のB/S基準日時点で算出し、DBには保存しない。
- PCでは横長の表、モバイルでは項目名付きカードとして表示する。
- 登録内容から配偶者有無、相続順位、相続人数を集計し、既存の相続税計算条件へ同期する。

## 11. 相続税連携

### 11.1 連携方式

| 方式 | 挙動 |
|---|---|
| 相続税シミュレーターを開く | PBの顧客IDをクエリで渡し、シミュレーター側で明細を取得する |
| APIで相続税を計算 | PBサーバーから相続税計算APIを呼び、結果を現在年度へ保存する |

「相続税計算の家族情報」モーダルは家族情報と手動調整額の保存だけを行う。計算と税額更新は、モーダル外の「APIで相続税を計算」から明示的に実行する。

### 11.2 PBからの計算入力

```text
概算遺産額 = max(0, 現在年度の資産合計 - B/S算入負債合計)
```

小規模宅地等の特例を選択した土地は、概算遺産額から減額して送る。

```text
特例減額 = Σ（対象明細の評価額 × 減額割合 × min(1, 限度面積 ÷ 面積)）

API計算用遺産額 = max(0, 概算遺産額 - 特例減額)
```

| 選択肢 | 減額割合 | 限度面積 |
|---|---:|---:|
| 特定居住用宅地 | 80% | 330㎡ |
| 特定事業用宅地 | 80% | 400㎡ |
| 貸付事業用宅地 | 50% | 200㎡ |

- 限度面積を超える分は面積按分で減額する。面積が未入力の明細は全部が限度内として扱う。
- 併用時の限度面積の調整、要件充足の判定は行わない。画面上で要件確認を促す注記を表示する。
- 概算遺産額は1万円単位へ丸める。
- 配偶者有無、相続順位、人数を送る。
- 配偶者取得方法は法定相続分とする。
- 個人保証は負債として控除しない。

### 11.3 みなし相続財産の調整

B/Sに載っている解約返戻金（解約手当金）を、相続税の計算では給付金へ置き換える。
**非課税枠の計算そのものはPBでは行わず**、置き換えに必要な材料を相続税APIへ渡して任せる。
PBが持っているのは受取人の氏名であって相続人の資格ではないため、相続人としての扱いはAPI側の相続人構成に合わせる。

送るもの（生命保険・退職金それぞれ）:

- 解約返戻金（解約手当金）の合計額
- 契約ごとの給付金額と受取人区分。受取人区分は 配偶者／n番目の相続人／法定相続人以外 の3択とする

- 受取人区分は、受取人の氏名を親族関係の登録と突き合わせて決める。同姓同名は先に登録された相続人として扱う。
- 法定相続人以外が受取人の分は、受取人へ帰属させず按分に混ぜる（相続人以外の取得者としては計算しない）。実務との差が出るため件数を数えて警告に使う。
- 非課税枠（500万円 × 法定相続人数）は生命保険と退職金で別枠とし、API側で適用する。適用額・課税対象額・相続人ごとの帰属額は計算結果として受け取って表示・保存する。
- 給付金および解約返戻金は1万円単位へ丸めて送信する。
- API成功時、算出税額を顧客と現在年度の双方へ保存する。
- API成功時、入力元B/S、適用ルール、控除・加算、相続人別内訳を含む詳細結果を現在年度へJSONで保存する。
- 接続失敗、応答不正、APIエラーは502として扱い、既存税額を上書きしない。

### 11.4 計算過程の表示・印刷

- 貸借対照表画面に「相続税の概算」を表示する。
- 左側に財産評価額から納付税額までの計算、右側に控除・加算の根拠、下部に相続人別内訳を配置する。
- 計算後にB/Sまたは家族構成が変わった場合は、再計算を促す警告を表示する。
- 葬式費用、生前贈与加算、未成年者・障害者控除等が概算に含まれないことを明示する。小規模宅地等の特例は明細で選択した分だけ概算に反映する。
- 計算エンジンのバージョン、適用ルール基準日、計算日時を表示する。
- 印刷はA4横1ページに収め、画面より情報密度を上げた帳票形式とする。
- 手動で相続税額を更新した場合、保存済みの詳細計算結果は無効化する。

### 11.5 二次相続の試算

相続税の概算画面から、一次相続で配偶者が取得する割合を振って、一次・二次の税額合計を比べる。

- 配偶者の固有財産（万円単位）を入力して実行する。
- 配偶者取得割合は0%、25%、50%、75%、100%の5パターンを試算する。
- 一次相続は現在年度のB/Sから作る計算入力（`11.2`・`11.3`）の取得割合だけを差し替えて計算する。
- 二次相続は「配偶者の固有財産 ＋ 一次で配偶者が取得した財産」を遺産額とし、配偶者なし・第1順位（子）のみが相続すると仮定して計算する。遺産額は1万円単位へ丸める。
- パターンごとに 一次税額、配偶者取得額、二次相続の遺産額、二次税額、合計税額を表示し、合計税額が最小のパターンを目安として示す。
- 試算結果は保存しない（年度の税額を書き換えない）。
- 配偶者がいない場合、または第1順位（子）を選んでいない場合は試算できない（422）。
- 二次相続までの財産の増減、贈与、小規模宅地等の特例の適用替えは考慮しない。

### 11.6 連携設定

| 環境変数 | 用途 | 開発時既定値 |
|---|---|---|
| `INHERITANCE_TAX_API_URL` | 相続税計算API | `http://inheritance-tax-app:3004/inheritance-tax-app/api/calculate` |
| `INHERITANCE_TAX_API_KEY` | Bearer APIキー | 未設定 |

## 12. バックアップ

### 12.1 形式

- JSON形式
- `schemaVersion = 1`
- 種別は `full` または `household`
- 作成日時、顧客、年度、明細、保存済みの相続税計算結果を含む

### 12.2 操作

| 操作 | 仕様 |
|---|---|
| 全体を書き出す | 全顧客・全年度・全明細を保存 |
| 顧客を書き出す | 選択顧客のみ保存 |
| 顧客を取り込む | 新規顧客として追加 |

書き出しは「バックアップ」画面、取り込み・復元は「データ復元」画面に分ける。書き出すつもりで全体復元に触れる余地を残さないため、同じ画面には置かない。相互のリンクは双方に置く。

全体復元は破壊的操作である。画面で明示的な確認を行い、事前の全体書き出しを案内する。ファイルを選んだ後、内容（顧客数・年度数・明細数）を確認してから実行する。種別が合わないファイル（全体／顧客単位の取り違え）は実行せず、正しい操作へ案内する。

### 13.1 印刷対象

- 相続税の概算
- 貸借対照表
- 資産・負債明細
- 年度比較

利用者は複数セクションを選択できる。選択肢の並び、目次の並び、印刷されるページの並びはすべてこの順に従う。相続税の概算は概算税額を計算した後でなければ選択できない。貸借対照表を選択した場合は「税金なし」「税金あり」の両方を印刷する。

### 13.2 ページ構成

1. 表紙
2. 目次
3. 選択した資料

- 用紙はA4横向き。
- 各ページ下中央にページ番号を付与する。
- 表紙は白背景とし、余白、文字階層および罫線を中心に構成する。
- 表紙には顧客名、顧客コード、対象年度、B/S基準日を表示する。
- 本人情報と家族一覧は1ページにまとめる。
- 本人情報には氏名、生年月日、B/S基準日時点の年齢を表示する。

- 家族一覧には氏名、続柄、民法上・税法上の法定相続分、生年月日、B/S基準日時点の年齢、および税額の加算・控除（2割加算、配偶者税額控除、未成年者控除、障害者控除）をこの順に表示する。
- 税額の加算・控除は「該当あり」「該当なし」だけを表示し、区分や控除額は表示しない。判定できないとき（生年月日が未登録で年齢が出ない場合の未成年者控除）は「－」とする。
- 配偶者税額控除、未成年者控除、障害者控除は法定相続人にあたる親族だけを該当ありとする。2割加算は登録値をそのまま表示する。
- 家族一覧の下に、2割加算と配偶者税額控除は概算税額に反映済みであり、未成年者控除・障害者控除は反映していない旨を注記する。
- 目次には選択した資料のみ掲載する。
- 画面操作用の「一覧に戻る」、サイドバー、ボタン、モーダル等は印刷しない。

## 14. API仕様

すべてのアプリ内APIは `/private-banking/api` 配下とする。

| Method | Path | 用途 |
|---|---|---|
| GET / POST / PATCH / DELETE | `/clients` | 顧客一覧・作成・更新・削除 |
| GET | `/portfolio?householdId={id}` | 顧客ポートフォリオ取得 |
| GET | `/properties` | 全顧客の現在年度の不動産明細一覧 |
| POST | `/positions` | 明細追加 |
| PUT / DELETE | `/positions/{id}` | 明細更新・削除 |
| POST / PUT / PATCH | `/positions/bulk` | 表形式の追加・更新・一括管理 |
| PUT | `/positions/reorder` | 明細並び順保存 |
| PUT | `/family-members` | 家族情報一括保存・相続人構成同期 |
| POST | `/snapshots` | 年度追加 |
| PUT / DELETE | `/snapshots/{id}` | 年度税額更新・年度削除 |
| PUT | `/inheritance-estimate` | 家族情報・予測値更新 |
| GET | `/inheritance-export?householdId={id}` | 相続税シミュレーター向け明細出力 |
| POST | `/inheritance-tax-calculate` | 相続税API呼び出し・税額保存 |
| POST | `/inheritance-tax-secondary` | 二次相続の試算（保存しない） |

| POST | `/backup/import` | 顧客バックアップ取り込み |
| POST | `/backup/restore` | 全体バックアップ復元 |
| GET | `/health` | ヘルスチェック |

一般的なステータスコード:

- `200`: 取得・更新成功
- `201`: 作成成功
- `204`: 削除成功
- `400`: 入力不正

## 15. データモデル

### 15.1 Household

顧客基本情報、現在の予測税額、承継関連費用、相続人構成を保持する。顧客コードは一意とする。

### 15.2 Snapshot

年度別のB/S、相続税、その他税金を保持する。

- `Household 1 : N Snapshot`
- `(householdId, fiscalYear)` は一意
- 顧客削除時に連鎖削除

### 15.3 Position

年度別の資産・負債・偶発債務明細を保持する。

- `Snapshot 1 : N Position`
- 金額は通貨建て金額、換算レート、円換算時価を保持
- 科目固有項目は `assetDetails` JSONへ保存
- `sortOrder` で登録順を保持
- 年度削除時に連鎖削除

### 15.4 FamilyMember

顧客単位の家族、続柄、法定相続分、税務上の属性を保持する。

- `Household 1 : N FamilyMember`
- 法定相続分は民法上・税法上をそれぞれ分子と分母で保持
- `sortOrder` で表示順を保持
- 顧客削除時に連鎖削除
- 全体／顧客単位バックアップの対象に含める

## 16. 入力・表示共通仕様

- 金額は3桁区切りで表示する。
- DBへ保存する円金額は整数へ丸める。
- 日付は「1978（昭和53）年12月22日」の形式で表示する（西暦を主に、和暦は年だけを括弧で添える）。月日は西暦と和暦で同じなので繰り返さない。
- 年度は「2026年度」、印刷など幅に余裕のある箇所では「2026（令和8）年度」と表示する。和暦は年度の数字ではなくB/S基準日から求める（改元年を外さないため）。
- 生年月日などの日付欄は、西暦入力と和暦入力を切り替えられる。和暦は元号・年・月・日を選んで入力し、西暦へ変換して保存する。
  - 選んだ元号の期間外の日付は受け付けない（「昭和64年1月8日」「平成31年5月1日」等）。
  - 対応する元号は明治以降とする。
- 一覧（顧客一覧・不動産一覧）の表示件数は25件・50件・100件から選べる（既定25件）。件数が減って現在のページが範囲外になった場合は端のページへ寄せる。
- 検索語の一致部分は一覧上で強調表示する。ひらがな・カタカナ・全角半角の違いは吸収する。
- 負の資産・負債額は許可しない。
- 削除のうち、取り消せるもの（明細・家族）は確認ダイアログを出さず「元に戻す」を6秒間表示する。取り消せないもの（顧客・年度）は確認入力を求める。
- フォームエラーは日本語で表示する。
- モーダルはキーボード操作とフォーカス表示に対応する。
- `prefers-reduced-motion` 指定時はアニメーションを最小化する。
- モバイルでは表・フォームを1カラムまたは横スクロール可能な表示へ切り替える。

## 17. 非機能・運用要件

### 17.1 Docker

- 開発・ビルド・運用はDockerで行う。
- 開発でもソースはマウントせず、イメージ同梱物で動作する。編集内容は `docker compose watch` で同期する（`docker/scripts/manage.sh watch private-banking` をフォアグラウンドで起動）。
- 本番はNext.js standalone出力を使用する。
- DBマイグレーションはコンテナ起動時に適用する。
- 本番Webコンテナは読み取り専用ルートFS、非rootユーザー、`no-new-privileges`で動作する。
- コンテナは `tax-apps.autoheal=true` ラベルを持ち、unhealthy になった場合はホスト側ウォッチドッグの再起動対象となる。

#### 17.1.1 ソースをマウントしない理由

Docker Desktop for Windows の bind mount（Windows→WSL2）は、起動直後の `scandir` が `EFAULT` を返すことがある。Next.js の dev サーバはルート表を watchpack の初期スキャン結果から組み立てるため、スキャンに失敗したディレクトリ配下のルートが警告1行だけ残して**丸ごと欠落**し、`✓ Ready` の表示のまま該当ルートが 404 を返し続ける。`/api/health` は影響を受けないため healthcheck も healthy のままとなり、障害が表面化しない。

コンテナ内から bind mount を除去することでこの経路自体を無くす。代償として、Docker の sync がオーバーレイ上位層へ直接書き込みコンテナ内 inotify が発火しないため、次の2つのポーリング設定を併用する。

| ノブ | 場所 | 担当 |
|---|---|---|
| `WATCHPACK_POLLING=true` | `docker-compose.yml` の `environment` | ルート表の更新 |
| `watchOptions.pollIntervalMs` | `next.config.ts` | Turbopack の再コンパイル |

#### 17.1.2 初期スキャン失敗の検知

上記は原因経路を除去済みだが、再発時に静かに壊れないよう、開発モードでのみ `docker-entrypoint.sh` が dev サーバの出力を監視する。`Watchpack Error (initial scan)` を検知した場合はコンテナを異常終了させ、`restart: unless-stopped` による再起動に委ねる。

- 監視は FIFO 経由で行い、dev サーバは `exec` せず子プロセスとして起動する（PID 1 はハンドラを持たないシグナルを無視するため）。
- `docker stop` の `TERM`/`INT` は `trap` で子プロセスへ転送する。
- 本番モード（`NODE_ENV=production`）ではこの監視は動作しない。

### 17.2 データ保全

- 複数テーブルを更新する処理はPrismaトランザクションを使用する。
- バックアップの復元・取り込み前にスキーマを検証する。
- 全体復元以外では、対象外顧客のデータを変更しない。

### 17.3 セキュリティ上の境界

- 相続税APIは任意でBearer APIキーを使用できる。
- 現時点でPrivate Bankingアプリ独自のログイン・権限管理は実装していない。
- 外部公開する場合は、Nginx等の上位レイヤーで認証、TLS、アクセス制限を必須とする。
- PostgreSQLの本番パスワードは環境変数で明示し、既定値を使用しない。

### 17.4 テスト

- 入力スキーマと評価算式
- 顧客・年度・明細の作成、更新、削除
- 並び替えと表形式一括編集
- バックアップの書き出し・取り込み・復元
- 相続税APIリクエスト生成

- Lint、TypeScript型検査、本番Dockerビルド

## 18. 制約・注意事項

- B/Sの時価は相続税評価額と一致するとは限らない。相続税計算前に評価替えを確認する。
- PBからの直接計算は法定相続分による概算であり、代襲相続や個別の取得割合等は相続税シミュレーターで調整する。
- 死亡保険金・死亡退職金の非課税枠は、受取人が親族関係に登録された法定相続人である明細にのみ適用する。受取人の法的資格をシステムが判定するものではないため、親族関係の登録内容が前提となる。
- 小規模宅地等の特例は明細で選択した区分による概算であり、要件充足の判定、併用時の限度面積の調整は行わない。
- 二次相続の試算は、一次相続の配偶者取得割合を振った概算の比較であり、二次相続までの財産の増減や贈与を考慮しない。
- 建物の床面積は記録用であり、評価額の計算には使わない。
- 個人保証は偶発債務であり、概算遺産額から控除しない。
- ブラウザの印刷機能やPDF生成エンジンによっては、CSSページ番号の対応状況が異なる場合がある。
