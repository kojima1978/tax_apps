## 2. 概要

### 2.1 目的

顧客単位で個人資産、負債、偶発債務を年度別に管理し、次の業務を支援する。

- 現在の貸借対照表の可視化
- 相続発生時の死亡保険金、税金、承継関連費用を含む予測
- 資産・負債明細の個別入力および表形式での一括編集
- 最大3年度の残高比較
- 相続税シミュレーターとのAPI連携
- 顧客単位または全体のJSONバックアップ
- 顧客説明用レポートの印刷・PDF出力

### 2.2 対象ユーザー

- 税理士法人、金融機関等の担当者
- PCでの登録・編集を主用途とし、タブレットやモバイルでの閲覧にも対応する

## 3. URL・画面構成

| URL | 画面 | 主な機能 |
|---|---|---|
| `/private-banking` | 顧客一覧 | 顧客検索、選択、新規登録 |
| `/private-banking/customers/{id}/balance` | 貸借対照表 | 現在価値・相続時予測の表示、税額API連携 |
| `/private-banking/customers/{id}/positions` | 資産・負債明細 | 年度選択、明細編集、表編集、並び替え |
| `/private-banking/customers/{id}/history` | 年度比較 | 3年度比較、年度作成・削除 |
| `/private-banking/customers/{id}/backup` | 顧客バックアップ | 顧客単位JSONの書き出し |
| `/private-banking/backup` | 全体バックアップ | 全データの書き出し・復元、顧客取り込み |

共通サイドバーは「貸借対照表」「資産・負債明細」「年度比較」「バックアップ」で構成する。外部連携として相続税シミュレーターへのリンクを表示する。

## 4. 顧客管理

### 4.1 顧客項目

| 項目 | 必須 | 制約・用途 |
|---|---:|---|
| 顧客コード | 必須 | 一意。検索および削除確認に使用 |
| 顧客名 | 必須 | 画面・印刷に表示 |
| 顧客名かな | 任意 | 顧客検索に使用 |
| 担当者 | 任意 | 顧客識別情報 |
| 基準通貨 | 必須 | 3文字。通常はJPY |
| 初期年度 | 新規時必須 | 1900～2200 |

### 4.2 新規作成

- 顧客作成時に、指定年度の現在スナップショットを1件作成する。
- 同一顧客コードは登録できない。

### 4.3 削除

- 顧客コードを確認入力し、一致した場合のみ削除できる。
- 顧客削除により、配下の全年度・全明細を連鎖削除する。
- 削除は取り消せないため、画面上で事前バックアップを案内する。

## 5. 年度管理

### 5.1 基本仕様

- 1顧客・1年度につきスナップショットは1件とする。
- 顧客内で最も新しい年度を「現在年度」とする。
- 基準日は作成年度の12月31日とする。
- 年度は1900～2200の整数とする。

### 5.2 年度追加

| 作成方法 | 明細 | 相続税・その他税金 |
|---|---|---|
| 前年度からコピー | コピーする | コピーする |
| 空の年度を作成 | 0件 | 0円 |

- 既存年度と重複する場合は作成せず、既存年度の編集へ誘導する。
- 現在より新しい年度を作成した場合、従来の現在年度を過年度へ変更し、新年度を現在年度にする。
- 過去の年度を追加した場合、現在年度は変更しない。

### 5.3 年度削除

- 対象年度を確認入力し、一致した場合のみ削除する。
- 顧客に残る唯一の年度は削除できない。
- 現在年度を削除した場合、残存する最新年度を現在年度へ昇格する。

## 6. 貸借対照表

### 6.1 表示区分

資産側と負債・純資産側を面積比で可視化する。金額と構成比を併記する。

#### 資産

- 金融資産
  - 預金・現金
  - 有価証券
  - 生命保険
- 不動産
  - 自宅
  - 収益不動産
  - 遊休不動産
- 事業用資産
  - 自社株
  - 事業用資産
  - 貸付金
- その他資産

#### 負債・純資産

- 税金
  - 相続税
  - その他税金
- 借入金
  - 住宅ローン
  - 不動産投資ローン
  - 証券担保ローン
  - 事業用借入
  - その他借入金
- 承継関連費用
- 純資産

個人保証は偶発債務としてB/S外に表示し、純資産計算には含めない。

### 6.2 表示シナリオ

| シナリオ | 生命保険 | 税金 | 承継関連費用 |
|---|---|---|---|
| 税金なし | 解約返戻金 | 0円 | 0円 |
| 税金あり | 死亡保険金 | 相続税＋その他税金 | 顧客単位の設定額 |

計算式:

```text
現在純資産 = 資産合計 - B/S算入負債

相続時予測資産 =
  現在資産合計 - 生命保険の解約返戻金合計 + 死亡保険金合計

相続時予測純資産 =
  相続時予測資産 - B/S算入負債 - 相続税 - その他税金 - 承継関連費用
```

- 死亡保険金未入力の契約は、相続時予測では0円として扱い、注意を表示する。
- 外貨建て死亡保険金は、登録された円換算レートを乗じる。

## 7. 資産・負債明細

### 7.1 登録区分

| 区分 | DB上の扱い | 純資産への算入 |
|---|---|---:|
| 資産の部 | `side = ASSET` | 加算 |
| 負債の部 | `side = LIABILITY` | 減算 |
| 偶発債務の部 | `side = LIABILITY`、個人保証 | 算入しない |

### 7.2 科目

#### 資産

`DEPOSIT`、`SECURITIES`、`HOME_REAL_ESTATE`、`REAL_ESTATE`、`IDLE_REAL_ESTATE`、`PRIVATE_SHARES`、`BUSINESS_ASSETS`、`LOAN_RECEIVABLE`、`INSURANCE`、`COLLECTIBLES`

#### 負債・偶発債務

`LOAN_HOME`、`LOAN_INVESTMENT_PROPERTY`、`LOAN_SECURITIES`、`LOAN_BUSINESS`、`LOAN_OTHER`、`GUARANTEE`

### 7.3 中分類

| 中分類 | 対象科目 |
|---|---|
| 金融資産 | 預金・現金、有価証券、生命保険 |
| 不動産 | 自宅、収益不動産、遊休不動産 |
| 事業用資産 | 自社株、事業用資産、貸付金 |
| その他資産 | その他資産 |
| 借入金 | 各借入金 |
| 個人保証 | 個人保証 |

中分類は文字ラベル、区切り線および最小限の色差で識別する。

### 7.4 共通入力項目

- 登録区分
- 科目
- 名称
- 金融機関・保管先等
- 通貨
- 金額
- 円換算レート
- 評価方法
- 備考

円換算時価は次式で保存する。

```text
円換算時価 = round(算出された通貨建て金額 × 円換算レート)
```

### 7.5 評価算式

| 評価方式 | 算式 | 対象 |
|---|---|---|
| `MANUAL` | 入力金額 | 全般 |
| `STOCK` | 株数・口数 × 単価 × 調整率 | 有価証券、自社株 |
| `LAND_ROADSIDE` | 面積 × 路線価 × 調整率 × 持分 | 土地 |
| `LAND_MULTIPLIER` | 固定資産税評価額 × 倍率 × 調整率 × 持分 | 土地 |
| `BUILDING` | 固定資産税評価額 × 倍率 × 調整率 × 持分 | 建物 |

不動産は所在地、土地・建物区分、持分の分子・分母を必須とする。貸付金は借主を必須とする。自社株の保有株数は発行済株式総数を超えてはならない。

### 7.6 生命保険固有項目

- 保険種類
- 被保険者
- 受取人
- 死亡保険金
- 非課税枠の対象
- 評価日

「非課税枠の対象」は、死亡保険金の受取人が法定相続人の場合に選択する。

### 7.7 表で編集・追加

一つの表で登録済み行の編集と新規行の追加を行う。

- 対象: 有価証券、自社株、土地、建物
- 種類ごとに既存明細を読み込み、末尾へ新規行を表示する
- Excel等から複数セルを貼り付け可能
- Enterで次の編集可能セルへ移動
- Shift+Enterで前の編集可能セルへ移動
- 行複製、新規行削除、一括保存に対応
- 登録済み行は表内で更新し、削除は明細一覧の個別削除から行う
- 不動産の表入力金額は千円単位で表示し、保存時に円へ変換する

### 7.8 並び替え・絞り込み

- 登録順ではドラッグ＆ドロップで並び替えできる。
- 並び替えハンドルにフォーカスし、上下矢印キーでも移動できる。
- 中分類フィルターが「すべて」、表示順が「登録順」の場合のみ手動並び替えを許可する。
- 表示順は「登録順」「中分類順」「中分類の逆順」から選択できる。

## 8. 年度比較

- 任意の3年度を選択して比較する。
- 選択年度は自動的に時系列順へ並べる。
- 最新選択年度と直前選択年度の差額を表示する。
- 金融資産、不動産、事業用資産、税金、借入金は小分類を展開できる。
- 年度一覧には基準日、状態、資産合計、負債合計、純資産、個人保証を表示する。

## 9. 相続税連携

### 9.1 連携方式

| 方式 | 挙動 |
|---|---|
| 相続税シミュレーターを開く | PBの顧客IDをクエリで渡し、シミュレーター側で明細を取得する |
| APIで相続税を計算 | PBサーバーから相続税計算APIを呼び、結果を現在年度へ保存する |

「相続税計算の家族情報」モーダルは家族情報と手動調整額の保存だけを行う。計算と税額更新は、モーダル外の「APIで相続税を計算」から明示的に実行する。

### 9.2 PBからの計算入力

```text
概算遺産額 = max(0, 現在年度の資産合計 - B/S算入負債合計)
```

- 概算遺産額は1万円単位へ丸める。
- 配偶者有無、相続順位、人数を送る。
- 配偶者取得方法は法定相続分とする。
- 個人保証は負債として控除しない。

### 9.3 生命保険の調整

相続税APIでは、B/Sに含まれる解約返戻金を死亡保険金へ置き換える。

```text
法定相続人数 = 配偶者（いる場合は1人） + 選択順位の相続人数
死亡保険金の非課税限度額 = 500万円 × 法定相続人数

適用非課税額 =
  min(非課税枠対象契約の死亡保険金合計, 非課税限度額)

課税対象死亡保険金 =
  全死亡保険金合計 - 適用非課税額

API計算用遺産額 =
  概算遺産額 - 解約返戻金合計 + 課税対象死亡保険金
```

- 「非課税枠の対象」が未選択の契約には非課税枠を適用しない。
- 死亡保険金および解約返戻金は1万円単位へ丸めて送信する。
- API成功時、算出税額を顧客と現在年度の双方へ保存する。
- 接続失敗、応答不正、APIエラーは502として扱い、既存税額を上書きしない。

### 9.4 連携設定

| 環境変数 | 用途 | 開発時既定値 |
|---|---|---|
| `INHERITANCE_TAX_API_URL` | 相続税計算API | `http://inheritance-tax-app:3004/inheritance-tax-app/api/calculate` |
| `INHERITANCE_TAX_API_KEY` | Bearer APIキー | 未設定 |

## 10. バックアップ

### 10.1 形式

- JSON形式
- `schemaVersion = 1`
- 種別は `full` または `household`
- 作成日時、顧客、年度、明細を含む

### 10.2 操作

| 操作 | 仕様 |
|---|---|
| 全体を書き出す | 全顧客・全年度・全明細を保存 |
| 顧客を書き出す | 選択顧客のみ保存 |
| 顧客を取り込む | 新規顧客として追加 |
| 全体を復元する | 現在の全顧客データを削除し、バックアップ内容で置換 |

全体復元は破壊的操作である。画面で明示的な確認を行い、事前の全体書き出しを案内する。

## 11. 印刷・PDF出力

### 11.1 印刷対象

- 貸借対照表
- 資産・負債明細
- 年度比較

利用者は複数セクションを選択できる。貸借対照表を選択した場合は「税金なし」「税金あり」の両方を印刷する。

### 11.2 ページ構成

1. 表紙
2. 目次
3. 選択した資料

- 用紙はA4横向き。
- 各ページ下中央にページ番号を付与する。
- 表紙には顧客名、顧客コード、対象年度、B/S基準日を表示する。
- 目次には選択した資料のみ掲載する。
- 画面操作用の「一覧に戻る」、サイドバー、ボタン、モーダル等は印刷しない。

## 12. API仕様

すべてのアプリ内APIは `/private-banking/api` 配下とする。

| Method | Path | 用途 |
|---|---|---|
| GET / POST / PATCH / DELETE | `/clients` | 顧客一覧・作成・更新・削除 |
| GET | `/portfolio?householdId={id}` | 顧客ポートフォリオ取得 |
| POST | `/positions` | 明細追加 |
| PUT / DELETE | `/positions/{id}` | 明細更新・削除 |
| POST / PUT / PATCH | `/positions/bulk` | 表形式の追加・更新・一括管理 |
| PUT | `/positions/reorder` | 明細並び順保存 |
| POST | `/snapshots` | 年度追加 |
| PUT / DELETE | `/snapshots/{id}` | 年度税額更新・年度削除 |
| PUT | `/inheritance-estimate` | 家族情報・予測値更新 |
| GET | `/inheritance-export?householdId={id}` | 相続税シミュレーター向け明細出力 |
| POST | `/inheritance-tax-calculate` | 相続税API呼び出し・税額保存 |
| GET | `/backup` | JSONバックアップ出力 |
| POST | `/backup/import` | 顧客バックアップ取り込み |
| POST | `/backup/restore` | 全体バックアップ復元 |
| GET | `/health` | ヘルスチェック |

一般的なステータスコード:

- `200`: 取得・更新成功
- `201`: 作成成功
- `204`: 削除成功
- `400`: 入力不正
- `404`: 対象なし
- `409`: 重複・業務制約違反
- `502`: 外部相続税APIの接続または応答エラー

## 13. データモデル

### 13.1 Household

顧客基本情報、現在の予測税額、承継関連費用、相続人構成を保持する。顧客コードは一意とする。

### 13.2 Snapshot

年度別のB/S、相続税、その他税金を保持する。

- `Household 1 : N Snapshot`
- `(householdId, fiscalYear)` は一意
- 顧客削除時に連鎖削除

### 13.3 Position

年度別の資産・負債・偶発債務明細を保持する。

- `Snapshot 1 : N Position`
- 金額は通貨建て金額、換算レート、円換算時価を保持
- 科目固有項目は `assetDetails` JSONへ保存
- `sortOrder` で登録順を保持
- 年度削除時に連鎖削除

## 14. 入力・表示共通仕様

- 金額は3桁区切りで表示する。
- DBへ保存する円金額は整数へ丸める。
- 負の資産・負債額は許可しない。
- フォームエラーは日本語で表示する。
- モーダルはキーボード操作とフォーカス表示に対応する。
- `prefers-reduced-motion` 指定時はアニメーションを最小化する。
- モバイルでは表・フォームを1カラムまたは横スクロール可能な表示へ切り替える。

## 15. 非機能・運用要件

### 15.1 Docker

- 開発・ビルド・運用はDockerで行う。
- 開発はソースを読み取り専用でマウントし、ホットリロードする。
- 本番はNext.js standalone出力を使用する。
- DBマイグレーションはコンテナ起動時に適用する。
- 本番Webコンテナは読み取り専用ルートFS、非rootユーザー、`no-new-privileges`で動作する。

### 15.2 データ保全

- 複数テーブルを更新する処理はPrismaトランザクションを使用する。
- バックアップの復元・取り込み前にスキーマを検証する。
- 全体復元以外では、対象外顧客のデータを変更しない。

### 15.3 セキュリティ上の境界

- 相続税APIは任意でBearer APIキーを使用できる。
- 現時点でPrivate Bankingアプリ独自のログイン・権限管理は実装していない。
- 外部公開する場合は、Nginx等の上位レイヤーで認証、TLS、アクセス制限を必須とする。
- PostgreSQLの本番パスワードは環境変数で明示し、既定値を使用しない。

### 15.4 テスト

最低限、次を継続的に確認する。

- 入力スキーマと評価算式
- 顧客・年度・明細の作成、更新、削除
- 並び替えと表形式一括編集
- バックアップの書き出し・取り込み・復元
- 相続税APIリクエスト生成
- 生命保険の非課税枠対象判定
- Lint、TypeScript型検査、本番Dockerビルド

## 16. 制約・注意事項

- B/Sの時価は相続税評価額と一致するとは限らない。相続税計算前に評価替えを確認する。
- PBからの直接計算は法定相続分による概算であり、代襲相続や個別の取得割合等は相続税シミュレーターで調整する。
- 死亡保険金の非課税枠は、画面で「非課税枠の対象」とした契約にのみ適用する。受取人の法的資格をシステムが自動判定するものではない。
