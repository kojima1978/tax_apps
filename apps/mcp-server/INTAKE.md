# 取込の手順（AI 向け）

決算書・申告書の PDF が入ったフォルダから、株式評価明細書の案件へ数字を入れるときの手順。
**この手順書を読めば、誰がやっても同じ結果になる**ことを狙っている。

読む相手は AI（Claude Desktop / Cowork など）。人向けの説明は [README.md](README.md)。

---

## 大前提（これだけは崩さない）

1. **欄のことは `describe_fields` が教える。** この手順書に欄のコードは書かない
   ── 様式が変われば辞書が変わるので、ここに写すと古い対応表を見ながら書くことになる
2. **書く前に必ず試算**（`commit` を付けずに呼ぶ）。差分を人に見せ、**合意を得てから** `commit: true`
3. **資料から読み取った値には `source` を付ける**（ファイル名・ページ）。
   人の指示で直すだけのときは付けない
4. **金額の単位は千円**（様式どおり）。円で読んだ値は**自分で千円に直してから**渡す。
   MCP は換算しない ── 換算させると、丸めたことが誰の目にも残らない
5. **判断は人がする。** 読み取りと判断の線引きは「[人に聞くこと](#人に聞くこと)」のとおり
6. **取込の前に、その案件を開いている画面のタブを閉じてもらう**（開いたままだと
   ブラウザの自動保存が後から上書きする）

## 手順

### 0. 準備

```
describe_fields            # 入れられる欄の辞書。これを読まずに書き始めない
list_cases                 # 既にある案件
```

人に「どの会社の、いつの時点の評価か」を確かめる。課税時期は**相続開始の日**（被相続人の
死亡の日）で、決算期末ではない。資料から勝手に決めない。

### 1. 案件を用意する

```
create_case                # 会社名・課税時期・直前期（自・至）
```

- 同じ会社・同じ課税時期の案件が既にあれば、作らずにその `caseId` が返る。そのまま使う
- ゴミ箱に同じものがあるときは文面で知らせる。**復元するかどうかは人に聞く**
- 会社名は決算書の表紙どおりに（「株式会社」「有限会社」まで含めて）。
  一覧の見出しになるので、推測で短くしない

既にある案件へ入れるときは `create_case` を飛ばして `list_cases` の `caseId` を使う。

### 2. フォルダの PDF を仕分ける

ファイル名ではなく**中身**で見分ける（「決算書.pdf」に申告書が綴じ込まれていることがある）。
どの資料がどの様式に効くか:

| 読む資料 | 入る先 | 使う道具 |
| --- | --- | --- |
| 法人税申告書 別表一 | 第1表の1 の本店所在地・代表者氏名 | `set_fields` |
| 法人税申告書 別表二 | 第1表の1 の株主の明細／発行済株式数・議決権の総数・自己株式 | `import_rows` ／ `set_fields` |
| 貸借対照表 | 第1表の2 の総資産価額（帳簿価額） | `set_fields` |
| 損益計算書 | 第1表の2 の取引金額（売上高・営業収益） | `set_fields` |
| 別表四 | 第4表の1 の法人税の課税所得金額 | `set_fields` |
| 別表五（一） | 第4表の1 の資本金等の額・利益積立金額 | `set_fields` |
| 別表八（一） | 第4表の1 の受取配当等の益金不算入額 | `set_fields` |
| 別表七（一） | 第4表の1 の繰越欠損金の控除額 | `set_fields` |
| 株主資本等変動計算書 | 第4表の1 の年配当金額 | `set_fields` |
| 勘定科目内訳明細書 | 第5表の明細（科目・帳簿価額） | `import_rows` |

辞書の各欄には `hint` が付いていて、「別表五(一)Ⅱ の差引翌期首現在資本金等の額の合計」の
ように**どの資料のどこを見るか**が書いてある。迷ったら `describe_fields` の `hint` を読む。

**第4表の1 は3期分**（直前期・直前々期・直前々期の前期）。欄の `period` がどの期かを表す。
3期ぶんの申告書が揃っていないときは、揃っている期だけ入れて、残りを人へ報告する。

### 3. 現状を見る

```
get_case                   # 辞書に載っている欄の現在値、明細行、取込の控え、人が入れるもの
```

**既に入っている値を黙って上書きしない。** 人が手で入れたのかもしれない。
違う値になるときは、試算の差分で見せて人に確かめる。

### 4. 入れる（試算 → 確定）

入れる順番はこれ。前の表の結果を見てから次に進むため、まとめて一気に書かない。

1. **第1表の1 の会社情報**（本店所在地・代表者氏名）
2. **第1表の1 の株主**（`import_rows` の `shareholders`）→ 続けて発行済株式数・議決権の総数・自己株式
3. **第1表の2**（総資産価額・取引金額）
4. **第4表の1**（3期分）
5. **第5表の明細**（`import_rows` の `balanceSheet`）

各段で:

```
set_fields / import_rows                        # ← commit なし（試算）
  → 差分を人に見せる
set_fields / import_rows ... commit: true       # ← 合意が得られたら確定
```

試算の文面には「変わる欄」と「現在の値と同じだった欄」の両方が出る。**人に見せるのは
試算の文面そのまま**で、要約しない（どこが変わるかを人が自分の目で見られることが
2段階にしている理由）。

`source` の付け方:

```json
{ "source": "決算書.pdf", "page": 12, "note": "貸借対照表 資産の合計" }
```

- `note` は「どこを見たか」。あとで人が確かめ直すときの手がかりになる
- 読み切れなかった・自信がないときは `"uncertain": true`。画面で赤い印になり、
  人が確認する一覧の先頭に並ぶ。**推測で入れるときは必ず付ける**
- 明細行の控えは行ごとに先頭列（科目名・氏名）へ1つ付く

### 5. 第5表の明細（`import_rows`）で気をつけること

- **指定した側（資産／負債）は1行目から詰め直す。** その側の既存の行は全部消える。
  片側だけ入れ直したいときは、その側だけを指定する（指定しなかった側はそのまま）
- **科目をまとめない。** 内訳明細書に出ている科目の粒度のまま入れる
- **相続税評価額は入れない**（帳簿価額だけ）。路線価・取引相場のない株式の評価額は
  資料からは決まらない
- **備考（株式等・土地等）を推測しない。** 第5表の備考は評価の判断そのもの
- 行が本表（15行）に収まらないときは続紙の枚数欄も自動で増える。枚数は減らさない

### 6. 株主の表（`import_rows` の `shareholders`）で気をつけること

- **1行目は納税義務者**（相続人）。並び順は別表二の順ではないので、**人に確かめてから**渡す
- 続柄・役職の欄は辞書に無い（人が画面で入れる）
- 「筆頭株主グループの議決権の合計数」は、どこまでを同一グループと見るかの判断が入る。
  候補を出して人に決めてもらう

### 7. 最後に人へ報告する

```
get_case                   # intake（確認待ちの欄と出典）と manualItems（人が入れるもの）
```

報告はこの形で。**入れた話より、人がやることを先に書く**（取込の価値はそこにある）。

```
【人が画面で入れる欄】
- 第1表の2 従業員数（㋠継続勤務従業員数・㋷労働時間合計）── 決算書・申告書には出てこない
- 第5表 資産の相続税評価額 ── 帳簿価額からは決まらない
- 第1表の1 株主の続柄・役職 ── 同族関係者かどうかの判定。誤ると評価方式が変わる
- 第4表の2 類似業種の業種目番号 ── 候補: 〇〇（〇〇番）／〇〇（〇〇番）。確定は人
- （ほか manualItems に出たもの）

【自信がない欄（画面で赤い印）】
- 第4表の1 ⑦非経常的な配当金額（直前期）── 記念配当か通常の配当か資料から読み切れず

【資料が足りなかったところ】
- 直前々期の前期の別表四が見つからず、⑪法人税の課税所得金額が空のまま

【入れた欄】
- 第1表の1: 株主5件、発行済株式数・議決権の総数ほか3欄
- 第1表の2: 2欄 ／ 第4表の1: 18欄 ／ 第5表: 資産12行・負債6行
```

画面の「取込の確認」に同じ一覧が出る。人が値を直す／「確認済み」にすると印が消える。

## 人に聞くこと

資料を読めば決まることは自分で入れる。**判断が入るものは必ず人に聞く。**
迷ったら入れずに聞く ── 間違った数字が「自動で入った」として残るのが一番困る。

| 聞くこと | なぜ |
| --- | --- |
| 課税時期（相続開始の日） | 決算期末ではない。資料には書いていない |
| 株主の並び順（1行目が納税義務者か） | 誰が相続人かは資料からは決まらない |
| 筆頭株主グループの範囲 | 同族の判定が入る |
| 配当・利益が経常か非経常か | 記念配当・特別配当・固定資産売却益など。評価の判断 |
| 第5表の備考（株式等・土地等） | 評価の判断 |
| 類似業種の業種目番号 | 候補は出せるが確定は人 |
| 既に入っている値を上書きするか | 人が手で入れた値かもしれない |
| ゴミ箱の案件を復元するか | 消した判断を覆すことになる |

**自動化しないもの**（辞書に載っていないので MCP からは書けない。`get_case` の
`manualItems` がそのまま一覧）: 従業員数、第5表の相続税評価額、株主の続柄・役職、
類似業種の業種目番号。

## つまずいたときの読み替え

| 返ってきた文面 | 何をするか |
| --- | --- |
| 「… という様式は辞書にありません」 | `describe_fields` を引数なしで読み直す |
| 「… という欄は辞書にありません」 | `describe_fields` に載っている欄か。自動計算欄・転記欄は外から書けない |
| 「… には様式の略号が付いていません」 | `G01` だけでなく `4-1:G01` の形で指定する（記号は様式ごとに振り直されている） |
| 「… 小数は受け付けません」 | 円で読んだ値を千円にしたときの端数。人に丸め方を確かめる |
| 「… 行目: … が空です」 | 空行を挟んでいる。行は詰めて渡す |
| 「source.confirmed は渡せません」 | 「確認済み」は人が画面で立てる印。こちらからは付けない |
| 「出典（source）が付いていないので …」 | 資料から読み取った値なら `source` を付けて呼び直す |
| 接続できない（`SVF_API_BASE`） | 株式評価明細書が起動していない。人に起動を頼む |
