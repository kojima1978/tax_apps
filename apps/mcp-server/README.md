# tax-apps MCP サーバー

外部の AI ツール（Claude Desktop など）から**株式評価明細書**（`stock-valuation-form`）へ
数字を書き込むための MCP サーバー。通信は stdio。

想定している使い方はこれ:

1. 法人税の申告書・決算書・勘定科目内訳明細書の PDF を AI に読ませる
2. AI が読み取った数字を、この MCP サーバー経由で評価案件の該当欄へ入れる

**PDF を読むのは AI 側の仕事**で、このサーバーは読まない。ここがやるのは
「どの欄に何を入れられるか」を教えることと、入れる前に検査することだけ。

## 様式の知識はここに持たせない

どの欄が何かは、株式評価明細書が配る**欄の辞書**（`GET /stock-valuation-form/api/field-catalog`）
だけが決める。このサーバーには様式の表も、欄の対応表も、単位の換算も入っていない
（金額の桁区切りや負数の `△` すら辞書の `formats` から来る）。

様式が変われば辞書が変わり、このサーバーは何も直さなくてよい。逆にここに写しを
持つと、様式を直したときに**片方だけ古いまま黙って動く**状態ができる。

辞書に無いコード・自動計算欄・単位違い・小数混入はすべて弾く。

## 道具

| 道具 | 何をするか |
| --- | --- |
| `describe_fields` | 書き込める欄の辞書。**書く前に必ず読む** |
| `list_cases` | 評価案件（会社1社・課税時期1つぶん）の一覧。`includeArchived: true` でゴミ箱も含める |
| `create_case` | 案件を新しく作る（会社名・課税時期・直前期）。同じ会社・同じ課税時期があれば作らずそれを返す |
| `get_case` | 1件の現在値。辞書に載っている欄と明細行の表（＋続紙の枚数）、取込の控え（`intake`）と人が入れるもの（`manualItems`） |
| `set_fields` | コードで指定した欄へ書き込む |
| `import_rows` | 明細行の表を入れ替える（`balanceSheet` = 第5表の資産・負債、`shareholders` = 第1表の1 の株主） |

**書き込みは既定で試算**。差分を返すだけで案件は変わらない。確定するのは
`commit: true` を付けて呼び直したときだけ。

### 欄のコードは「様式の略号:識別記号」

`4-1:G01`、`1-2:G09` の形。識別記号は**様式ごとに G01 から振り直されている**ので、
記号だけでは欄が決まらない（第1表の1・第1表の2・第4表の1 の `G01` は全部別の欄。
`G09` は第1表の2 の総資産価額と第4表の1 の非経常的な配当金額の両方に実在する）。
略号を落として渡すと、候補を挙げて弾く。

このコードは辞書と MCP の中だけで使う。画面は様式どおりの表示に、保存データは
`table` と `field` しか持たないので、コードを振り直しても画面・DB・バックアップには影響しない。

### 入れられる範囲

| 読む資料 | 入る先 | 道具 |
| --- | --- | --- |
| 法人税申告書 別表二 | 第1表の1 の株主（氏名・株式数・議決権数） | `import_rows` |
| 貸借対照表 | 第1表の2 の総資産価額 ／ 第5表の帳簿価額 | `set_fields` ／ `import_rows` |
| 損益計算書 | 第1表の2 の取引金額 | `set_fields` |
| 別表四・別表五（一） | 第4表の1（法人税の課税所得金額・配当金額ほか） | `set_fields` |
| 勘定科目内訳明細書 | 第5表の明細（科目・帳簿価額） | `import_rows` |

**人が画面で入れる欄**は辞書に載せていない（＝MCP からは書けない）: 従業員数、
第5表の相続税評価額、評価方式の判断、株主の続柄・役職、類似業種の業種目番号。
どれも資料の読み取りではなく評価の判断なので、AI は候補を挙げるところまで。

明細の入れ替えは**その側を1行目から詰め直す**（指定しなかった側はそのまま）。
行が本表に収まらないときは**続紙の枚数欄も一緒に増やす** ── 行だけ書いて枚数を
足し忘れると、保存はされているのに画面にも印刷にも出ない。枚数は減らさない
（人が続紙を足して手で書き始めているかもしれないため）。

### 案件を作るときは欄まで埋まる

一覧に出る会社名と課税時期は、案件の列ではなく**第1表の1 の欄**（会社名・課税時期・直前期）から
作られる（株式評価明細書側が保存のたびに作り直す）。`create_case` は列と欄の両方を埋める ──
欄を空のままにすると、画面で開いた次の自動保存で見出しが「（会社名未入力 #12）」になり、
作ったはずの案件が一覧で見分けられなくなる。

どの欄がそれかも辞書が決める（`caseIdentity`。和暦の元号と期間もそこから来る）。
`平成40年` や `令和1年1月1日` のような成り立たない日付は、画面のプルダウンの網をくぐるので
こちらで弾く。月日が分からないときは年までで作れるが、「人が画面で入れる欄」として文面に出る。

## どこを自動で入れたかを残す（出典）

`create_case` / `set_fields` / `import_rows` は `source` を受け取る。付けると、入れた欄が
**画面で紫の印**になり、「取込の確認」の一覧に出る（印刷には出ない。様式に忠実に）。

```json
{ "source": "決算書.pdf", "page": 4, "note": "別表四の所得金額", "uncertain": false }
```

| 項目 | 何を入れるか |
| --- | --- |
| `source` | 読んだ資料のファイル名（必須） |
| `page` | その資料の何ページか |
| `note` | 読み取りのメモ（「別表四の所得金額」「中間配当と区別できず」など） |
| `uncertain` | 資料から読み切れず自信がないとき `true`。画面では**赤い印**になり、確認の一覧の先頭に並ぶ |

**資料から読み取った値には必ず付ける。** 付けないと、あとから人が「どの数字を誰がどこから
入れたのか」を追えない。付け忘れた呼び出しには、文面でそう知らせる。

逆に、**人の指示で直すだけのときは付けない**（「配当は非経常だから 0 にして」など）。
嘘のファイル名が控えに残るほうが害が大きい。出典なしで書いた欄は、**前の取込の控えを落とす**
── 人が直した値に古い出典が残ると、画面が「この数字は決算書から入った」と言い続けることになる。

控えの置き場所も鍵の形も辞書（`catalog.intake`）が決める。案件データの中の専用のバケットへ
`<バケット>.<保存キー>` の鍵で JSON 文字列として入るだけなので、DB のスキーマもバックアップの
形も変わらない。人が画面で値を直すと控えは落ち、「確認済み」にすると `confirmed` が立つ
（出典は残る）。**`confirmed` は MCP からは渡せない** ── 人が確認した事実を外から作れてしまうため。

明細行の控えは、行ごとに**先頭列（科目名・氏名）の1つ**だけに付く。全列に付けると確認の
一覧が列数ぶん膨れるし、見たいのは「この行がどの資料から入ったか」なので1つあれば足りる。
入れ替えで消えた行の控えも一緒に落とす。

## 人が画面で入れるものを最後に報告する

`get_case` の `manualItems` に「資料からは決まらないので人が画面で入れるもの」が入っている
（従業員数、第5表の相続税評価額ほか）。これも辞書が持っているので、取込の最後に
`get_case` を読んで、`intake` に残っている欄（＝まだ人が確認していない欄）と合わせて人へ返す。

**AI 向けの取込手順書は [INTAKE.md](INTAKE.md)。** どの資料からどの様式へ入れるか、入れる順番、
試算の見せ方、人に聞くこと、最後の報告の形までそこに書いてある。

## 使い方（Claude Desktop）

`%APPDATA%\Claude\claude_desktop_config.json` に追記する:

```json
{
  "mcpServers": {
    "tax-apps": {
      "command": "docker",
      "args": ["run", "-i", "--rm", "--network", "tax-apps-network", "tax-apps-mcp"]
    }
  }
}
```

事前に1回だけイメージを作る（`docker-compose.yml` のサービスには
`profiles: ["mcp"]` が付いているので、`manage.sh start` では起動しない）:

```bash
cd apps/mcp-server && docker compose --profile mcp build mcp-server
```

**株式評価明細書が起動している必要がある**（`tax-apps-network` 上のサービス名で叩く）。
接続先を変えるときは `SVF_API_BASE` 環境変数。既定は
`http://stock-valuation-form:3014/stock-valuation-form/api` で、dev（Vite のプロキシ）でも
本番（Node 直）でも同じ URL で通る。1リクエストの制限時間は `SVF_API_TIMEOUT_MS`（既定 15000）。
どちらも `docker run` の `-e` で渡す（compose の `environment` は `docker run` からは読まれない）。

イメージはソースを同梱するので、`src/` を直したら上の `build` をもう一度叩く
（作り直すまで Claude Desktop は古いイメージを起動し続ける）。辞書は起動のたびに読み直すので、
株式評価明細書の様式を直しただけならこちらの作り直しは要らない。

> dev サーバへ繋ぐには、Vite 側に `allowedHosts: ['stock-valuation-form']` が要る。
> Vite 7 は DNS リバインディング対策で localhost 以外の `Host` を 403 で弾くため
> （`apps/stock-valuation-form/vite.config.ts` に入れてある）。

## 取込中は画面を閉じておくこと

**画面でその案件を開いたまま MCP から書くと、どちらかの入力が失われる。**

案件の自動保存も同じ `PUT /cases/:id` を叩き、しかも `data` をまるごと置き換える。
株式評価明細書には楽観ロックがあり（画面は読んだときの `updatedAt` を `expectedUpdatedAt` で
送り、食い違えば 409）、画面が黙って上書きすることはもう無い。ただし守られるのは片側だけ:

- **MCP が書いた後に画面が保存しようとした場合**: 409 で自動保存が止まり、ヘッダに
  「読み直す」が出る。押すと MCP の書き込みが画面に入る代わりに、**画面で入れていたぶんは
  送られないまま消える**
- **MCP が読んでから書くまでの間に画面が保存した場合**: MCP は前提（`expectedUpdatedAt`）を
  送らないので、**画面の保存を黙って上書きする**（MCP は画面を持たないので前提を持ちようがない。
  必須にすると MCP が一切書けなくなるため、サーバ側で省略を許している）

なので運用は以前と同じ:

- 取込の前に、その案件を開いているタブを**閉じる**
- 取込が終わってから開き直す

同じサーバープロセスの中での書き込み同士は `src/lock.ts` が案件ごとに順番待ちにしている
（`set_fields` と `import_rows` を同時に呼ぶと、実際に第5表が丸ごと消えた）。
ただし防げるのはこのプロセスの中だけで、ブラウザとの競合は防ぎようがない。

## 案件データの扱い

**顧客の実名と財産内容が MCP クライアントへ渡る。** PDF を読ませる時点で同じ情報が
渡っているので新しく増える露出ではないが、渡っていること自体は変わらない。

## バックアップと復元

このサーバーは**データを持たない**ので、全体バックアップの対象ではない。書き込んだ数字は株式評価明細書の DB に入り、
そちらの全体バックアップ（[stock-valuation-form の README](../stock-valuation-form/README.md#バックアップと復元)）で守られる。
取り込みを間違えたときは、試算（`commit` なし）で確かめてから確定する運用が第一の守り。

## テスト

```bash
docker/scripts/manage.sh test mcp-server
```

常駐しないアプリなので、`TEST_TARGETS` では `run@mcp-server-test` 形式で登録してある
（稼働中のコンテナを探す代わりに `docker compose run --rm` で使い捨てのコンテナを立てる）。
同じ一覧が `.github/workflows/ci.yml` の matrix にもある。
